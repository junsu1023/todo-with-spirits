설계 원칙:
- **순수 검정 대신 따뜻한 갈색 검정**(#1B1815)을 써서 라이트의 따뜻한 톤을 이어간다. 표면은 배경 → 사이드바 → 카드 순으로 한 단계씩 밝아진다 (#1B1815 → #23201C → #2A2622).
- **본문은 순백이 아닌 크림색**(#EFE6DC)으로 눈부심을 줄였다. 대비는 12:1 이상이다.
- **라임은 다크 배경에서 살짝 밝힌 #C9E43A**를 쓰고, 버튼 글자는 거의 검정(#1B1F00)으로 둔다. 다크 모드에서 흰 글자 라임 버튼은 쓰지 않는다.
- **칩·태그는 진한 색 배경 + 밝은 같은 계열 글자**로 바꿨다 (라임 9.8:1, 핑크 8.7:1).
- 그림자는 색 대신 검정 투명도로 표현하고, 테두리(#3A342E)는 장식용이라 대비 기준 대상이 아니다. 대신 체크 원처럼 상태를 나타내는 테두리는 3:1 이상(#8C7C6C)으로 올렸다.
- 도감 그림 4종은 Figma 캡처에서 잘라 써서 흰 배경이 붙어 있다. 그래서 다크 모드에서도 그림 칸만 밝은 액자로 둔다. 투명 배경 원본을 받으면 이 처리를 없앨 수 있다.

## 4. 남은 일
- 결정됨: 라이트 기본값은 "대비 높이기" 켬. Figma 원본(모바일)에도 같은 글자색 보정을 반영할지는 디자이너와 협의가 필요하다.
- 실제 Windows 고대비 테마(시스템 설정)는 별도 대응이 필요하다 (`forced-colors` 미디어 쿼리).

## 7. 라이트 대비 높임 보정 (2026-11-25)

전체 화면을 자동 측정했더니 대비 높임 모드에서도 4.5:1 미달이 남아 있었다.
- `--grey`(`#CFCAC2`)는 흰 배경 1.6:1로 거의 보이지 않았다 → `#736A61`.
- `--text-2`(`#86735F`)는 흰 카드에서만 4.53이고 앱 배경 4.35, 보조 배경 4.00, 라임 칩 4.14로 미달이었다 → `#7B6955`.
- 보조 글자를 진하게 하면 본문과 구분이 사라져서 본문 `--text`도 `#7A6A58` → `#665646`(6.2~7.0:1)로 한 단계 내렸다. 본문 › 보조(갈색) · 3단계(회색) 순서는 명도와 색감으로 구분한다.
- 알림 시스템 글자·미정 표시(`--noti-sys`, `--tbd`)도 `#7B6955`로 맞췄다. 배너·스위치 켜짐(`#7A6A58`)은 흰 글자 5.2:1이라 그대로 둔다.
- 측정 범위: 홈(상세 패널·알림 포함), 캘린더 주간·월간·연간, 도감, 설정 13개 패널, 로그인 첫 화면, 정령의 숲. 비활성 버튼은 제외했다.
- 대비 높이기를 끄면 Figma 원색(1절)으로 돌아간다.

## 8. 남은 화면 점검 (2026-11-25, 로그인·정령의 숲·공통 요소·좁은 창)

다크 모드에서 로그인 5단계(시작·이메일 로그인·회원가입·인증·환영), 로그인 실패 창, 정령의 숲(알림 신청 토스트 포함), 알림 패널, 단축키 창, 시안 목록(index)을 열어 봤다. 라이트·다크 × 1280·960 창에서 전 화면 자동 측정도 다시 돌렸다.

| 쓰임 | 값 | 비고 |
|---|---|---|
| 진행 막대·단계 표시의 빈 칸 `--track` (새 토큰) | 라이트 `#F5F0EA` · 다크 `#4A433C` | 로그인 단계 표시, 도감 "만난 정령"·다음 하트 막대, 비밀번호 안전도. 다크에서 빈 칸이 배경과 같아 막대 길이를 알 수 없던 문제 |
| 로그인 "이메일로 로그인" 빛 번짐 (다크) | 투명도 .3 → .1 | 어두운 배경에서 핑크 번짐이 과했던 문제 |

다크와 상관없이 함께 고친 것:
- 도감 그림 위치: 창 크기 버튼·가장자리 끌기·사이드바 접힘처럼 브라우저 resize 없이 칸 크기가 바뀌면 정령 그림이 잘려 보였다. 칸 크기 변화를 직접 감지해 다시 맞춘다.
- 도감 "미보유만": 960 창에서 두 줄로 꺾이던 것을 한 줄로.
- 좁은 창 첫 화면: 저장된 창 크기·사이드바 숨김을 적용하기 전에 사이드바가 잠깐 펼쳐졌다가 접히던 문제. 적용 전에는 창을 그리지 않고(최대 1.5초), 그 순간의 접힘 전환도 끈다.
- 설정 데이터: 백업·동기화 중에 다른 패널로 옮기면 스크립트 오류가 나던 문제.
