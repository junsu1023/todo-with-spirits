화면별 API 연동 작업표

현재 Windows 앱의 12개 화면 묶음에서 사용자 동작과 필요한 서버 작업을 한 줄씩 대조했다. 번호는 작업 번호다. 한 API를 여러 화면이 공유하므로 엔드포인트 수와 다르다.

연결은 Windows 호출 코드와 백엔드 구현이 있는 항목이다. 백엔드 요청에는 기존 응답에 필요한 필드와 팀이 제공할 공식 URL도 포함한다. 기존·미연결은 Windows 화면이나 조작이 더 필요한 항목, 조건부 요청은 해당 제품 동작을 채택할 때 필요한 계약이다.

이미지는 현재 WPF 화면을 샘플 일정으로 렌더링했다. 계정 화면 두 장은 모의 API 응답을 사용했다. 이미지를 누르면 원본 크기로 볼 수 있다.

1. 홈 · 오늘의 일정

번호GUI에서 하는 일상태API 또는 데이터현재 동작 · 개발 요청
1오늘 일정 목록연결GET /api/task?from={from}&to={to}오늘 회차의 제목·시간·종일·중요·완료 여부로 카드를 그린다.
2남은 일정 수와 완료 수화면 계산오늘 회차의 isCompleted목록을 기준으로 전체·완료·남은 수를 집계한다. 집계 API는 필요 없다.
3다음 일정화면 계산endTime, isCompleted오늘 미완료 일정 중 현재 시각 이후 가장 이른 항목을 표시한다.
4어제 하지 못한 일연결GET /api/task?from={from}&to={to}오늘 이전 30일을 함께 읽어 미완료 단발 일정을 표시한다. 더 오래된 건은 조회 범위 밖이다.
5기한과 무관한 미완료 전체조건부 요청지난 미완료 조회 계약30일보다 오래된 일정까지 계속 이월할 때 필요하다. 날짜순 정렬과 다음 페이지 기준을 합의한다.
6검색화면 계산불러온 일정 제목검색어를 현재 목록에 적용한다. 모든 연도를 대상으로 하는 서버 검색창은 현재 GUI 범위 밖이다.
7중요 일정만 보기화면 계산isImportant별표 필터를 바꿔도 쓰기 요청이 나가지 않는다.
8완료 항목 숨기기화면 계산isCompleted완료 행의 표시만 바뀐다. 완료 취소와 구분한다.
9별표 켜기·끄기연결PATCH /api/task/{taskId}같은 일정의 isImportant를 바꾸고 목록을 갱신한다.
10카드 왼쪽 원으로 완료연결POST /api/task/{taskId}/complete?date={date}누른 회차 날짜로 완료한다. currencyEarned가 양수이면 획득한 정수를 표시한다.
11완료한 카드 다시 누르기연결DELETE /api/task/{taskId}/complete?date={date}같은 날짜의 완료를 취소한다. 서버는 지급한 정수를 회수한다.
12완료 직후 ‘되돌리기’연결같은 회차의 POST 또는 DELETE complete이번에 계정 모드에도 연결했다. 직전 상태로 복원하고 목록을 다시 읽는다.
13밀린 일정 ‘오늘 하기’연결PATCH /api/task/{taskId}/postponenewDate에 오늘을 보낸다. 성공 후 홈과 캘린더에서 새 날짜를 사용한다.
14모두 오늘 하기연결PATCH /api/task/{taskId}/postpone × 건수단건씩 순차 전송한다. 일부 성공 시 옮긴 건수를 알려 준다. 전부 성공하거나 전부 취소할 요구가 생기면 일괄 처리 계약이 필요하다.
15일괄 날짜 변경의 원자성조건부 요청여러 taskId와 대상 날짜를 받는 일괄 계약현재는 일부만 성공할 수 있다. 제품에서 전부 성공 또는 전부 취소를 요구할 때 추가한다.
16내일로 미루기연결PATCH /api/task/{taskId}/postpone단발 일정을 현재 예정일과 오늘 중 늦은 날의 다음 날로 옮긴다.
17미룬 날짜 되돌리기연결PATCH /api/task/{taskId}/postpone성공한 일정마다 이동 전 날짜를 다시 보낸다.

2. 일정 추가 · 상세 · 반복

번호GUI에서 하는 일상태API 또는 데이터현재 동작 · 개발 요청
18카드에서 상세 열기연결GET /api/task/{taskId}?date={date}공유된 반복 일정 ID에 선택 회차 날짜를 함께 전달한다.
19일정 추가 → 저장연결POST /api/task제목·날짜·종일 여부·중요·알림·반복을 전송한다. 성공 후 생성한 날짜로 목록을 갱신한다.
20제목 바꾸기연결PATCH /api/task/{taskId}계정 모드에서는 저장을 눌러야 반영된다. 로컬 모드는 기존 일정 수정 시 바로 저장한다.
21날짜 고르기연결PATCH /api/task/{taskId}패널의 달력은 PC에서 동작한다. 바뀐 일시를 endDateTime에 담아 저장한다.
22하루 종일 토글연결POST /api/task · PATCH /api/task/{taskId}isAllDay와 시간을 함께 보낸다. 시간 없는 일정에는 알림을 지정하지 않는다.
23시·분 지정연결endDateTime, isAllDay시간 지정 UI의 값을 일정 생성·수정 요청에 포함한다.
24매일 반복연결repeatType=DAILY날마다 서버가 펼친 회차를 표시하고 완료 날짜를 개별 관리한다.
25매주 반복 · 요일 선택연결repeatType=WEEKLY, repeatDaysOfWeek선택한 요일 배열을 보낸다. 값이 없으면 시작 요일을 사용한다.
26매월 반복 · 날짜 선택연결repeatType=MONTHLY, repeatDaysOfMonth선택한 일자 배열을 보낸다. 31일이 없는 달은 서버가 건너뛰고 로컬은 말일로 당긴다. 팀의 기준을 정해야 한다.
27반복 종료일기존·미연결repeatEndDate서버 생성·수정·조회 계약에 있다. 현재 편집기에 입력란이 없어 기존 값을 유지한다.
28공휴일 제외기존·미연결excludeHoliday요청·응답에 필드가 있고 기존 값을 보존한다. Windows 편집기에는 별도 스위치가 없다. 실제 공휴일 계산 방식은 별도 확인이 필요하다.
29기존 반복 일정의 시간만 수정백엔드 요청GET /api/task 및 GET /api/task/{taskId} 응답 확장occurrenceDate만으로는 첫날을 알 수 없다. startDate를 내려주거나 시작일을 건드리지 않는 시간 수정 계약이 필요하다.
30반복 일정 한 회차 미루기기존·미연결PATCH /api/task/{taskId}/postpone서버는 반복 유형별 제한과 originalDate를 사용한다. Windows의 미루기 메뉴는 반복 일정을 막는다. 재이동한 회차의 원래 날짜 식별을 포함해 지원 범위를 정한다.
3110분 전 알림연결notificationType=TEN_MINUTES일정 저장에 포함하며 응답의 notificationMinutes를 10분으로 읽는다.
3230분 전 알림연결notificationType=THIRTY_MINUTES일정 저장에 포함한다. Windows가 실행 중일 때 알림을 예약한다.
331시간 전 알림연결notificationType=ONE_HOUR60분 전으로 저장·표시한다.
34알림 없음연결notificationType=NONE시간을 끄거나 알림을 해제한 경우 이 값으로 저장한다.
35정각 알림백엔드 요청알림 열거형 0분 값 추가로컬 일정에는 있고 계정 일정에는 선택지가 없다. 0과 알림 없음이 요청·응답에서 구별되어야 한다.
36일정 삭제연결DELETE /api/task · body.taskIds현재 선택한 ID를 삭제한다. 반복 일정도 해당 ID 전체가 대상이다.
37반복 일정 이번 회차만 삭제조건부 요청taskId + 회차 날짜 + 삭제 범위문서 개요에 삭제 범위 용어가 있지만 현재 삭제 구현은 ID 목록으로 일정을 삭제한다. 회차만 지우는 GUI를 제공하려면 예외 회차 저장이 필요하다.
38삭제 직후 되돌리기조건부 요청동일 ID·회차 이력을 복원하는 계약로컬에는 삭제 취소가 있고 계정에는 없다. 같은 제목으로 새로 생성하면 이전 완료 이력이 복원되지 않는다.

번호GUI에서 하는 일상태API 또는 데이터현재 동작 · 개발 요청
48알림 목록 열기연결GET /api/notification?size=20계정 알림의 ID·분류·내용·생성 시각·읽음 상태를 표시한다. 명세에는 알림이 없을 때 개발용 더미를 준다고 적혀 있다.
49알림이 한 건도 없는 계정백엔드 요청GET /api/notification · 빈 content 배열개발용 더미를 제거하거나 환경별로 끌 수 있어야 실제 빈 상태와 미확인 배지를 검수할 수 있다.
50알림 더 보기연결GET /api/notification?size=20&cursor=…hasNext와 nextCursor를 사용하고 같은 ID의 중복 행을 제외한다.
51전체·시스템·이벤트·정령의 숲 탭화면 계산category현재 불러온 페이지에서 분류별로 필터링한다.
52종 배지·새 알림/지난 알림화면 계산read불러온 알림에 한해 미확인 개수를 집계한다. 전체 서버 미확인 수가 필요하면 총계 필드가 필요하다.
53알림 하나 열기연결PATCH /api/notification/{id}/read서버 알림이면 해당 건을 읽음 처리한다. PC 일정 리마인더면 연결된 일정을 연다.
54모두 읽음연결PATCH /api/notification/read서버의 전체 읽음 처리를 요청하고 화면에 불러온 행의 상태도 맞춘다.
55알림 하나 지우기조건부 요청현재 세션에서 숨김계정에 영구 반영하려면 단건 삭제 또는 숨김 API가 필요하다. 다른 기기에서는 지금도 볼 수 있다.
56모두 지우기조건부 요청현재 불러온 목록 숨김계정 전체 삭제가 필요하면 적용 범위를 정한다. 현재 동작은 아직 안 읽어 온 페이지까지 지우지 않는다.

60미보유만 보기화면 계산isOwned불러온 도감에서 미보유 종류를 고른다.
61정령 카드 선택화면 계산현재 도감 목록의 개체별도 상세 호출 없이 선택 카드의 상세 정보를 표시한다.
62호감도 하트연결GET /api/spirits · affectionLevel서버 단계 1~5를 하트 개수로 표시한다.
63다음 하트까지연결GET /api/spirits · affection이번에 기존 응답의 점수를 연결했다. 예를 들어 30점은 2단계이며 다음 하트까지 진행률은 50%다.
64이름 순·호감도 순 정렬화면 계산spiritName, affectionLevel보유 항목을 먼저 두고 정렬한다.

66대표 정령으로 설정연결PATCH /api/spirits/current선택한 보유 개체의 ID를 id로 전송한다.
67속성 표시백엔드 요청GET /api/spirits · 종류별 속성상세의 ‘속성’ 칸에 들어갈 바람·불 등의 값이 응답에 없다. 종류별 표시 값과 식별자를 요청한다.

확인 범위와 검증 결과

Windows WPF의 화면, 명령과 HTTP 요청을 원격 develop 커밋 efa0984의 Spring 컨트롤러·서비스·응답 모델에 대조했다. Confluence 데이터베이스의 표 행은 직접 읽을 수 없어 같은 공간의 API Docs와 개별 엔드포인트 명세를 확인했다.

네이버 클라우드 개발 환경의 HTTPS 주소에서 예시 이메일 중복 조회는 200 및 registered=false, 인증 없는 내 정보 조회는 401을 확인했다. 앱 기본 주소인 Render는 45초와 90초 확인에서 응답 시간이 초과됐다. 두 개발 환경의 계정 데이터가 같은지는 확인되지 않았다. 네이버 환경을 사용할 경우 실행 전에 PowerShell에서 $env:TODOSPIRITS_API_URL='https://custom-lucky-draw.store'를 지정한다.

Windows 빌드 및 모의 HTTP 호출로 일정 완료와 같은 날짜의 되돌리기, 다음 하트 진행률, 정령 이름과 즐겨찾기, 이메일 변경·재발송·인증, 구독 표시를 확인했다. 실제 계정의 메일 수신, 로그인 이후 배포 서버 쓰기, 다른 기기로의 반영은 미검증이다.
