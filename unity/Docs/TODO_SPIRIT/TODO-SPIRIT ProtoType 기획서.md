# 정령 동행 성장 프로젝트 — Prototype GDD v2.0

> **문서 버전:** v2.0  
> **기준일:** 2026-08-31  
> **문서 상태:** 프로토타입 제작 기준안  
> **대상:** Team.OOW
> **플랫폼:** 모바일 세로형(iOS/Android), 게임 파트 Unity  
> **핵심 문장:** **내가 살아낸 하루가 정령의 하루가 된다.**

---

## 0. 이 문서에서 확정하는 것

v2.0은 이전 v1.x의 시스템을 부분 수정한 문서가 아니다. 게임의 중심을 다시 정의하고 프로토타입에 필요한 규칙만 남긴 새 기준 문서다.

### 이번 버전의 핵심 변경

1. 게임을 `TODO 보상형 육성`이 아니라 **현실 연동 생활 시뮬레이션**으로 정의한다.
2. 사용자의 TODO는 정령의 능력치에 바로 더해지는 숫자가 아니라 **정령의 하루를 만드는 입력값**이 된다.
3. 정령은 사용자가 매일 명령하는 펫이 아니다. **대부분의 행동을 스스로 결정하고**, 사용자는 가끔 선물·여행·꾸미기 등으로 개입한다.
4. 정령에게는 2~3개의 **선천 기질**이 있다. 같은 사용자 기록이라도 정령마다 하루가 조금 다르게 전개된다.
5. 정령의 성장 기간은 정확한 28일 고정이 아니다. **약 4~6주의 활동 기간** 동안 생활 경험이 쌓여 자연스럽게 다음 단계로 넘어간다.
6. 성체가 되면 정령은 자신에게 맞는 **진로**를 찾는다.
7. 정령이 떠나기 전, 사용자가 처음으로 **정식 이름을 지어준다.**
8. 떠난 정령은 삭제되지 않는다. 동행 기록에 남고 이후 편지나 방문으로 다시 등장할 수 있다.
9. 첫 정령은 튜토리얼로 고정 제공한다. 이후 정령은 이전 정령이 남긴 **정령의 알 3~5개 중 하나를 선택**해서 만난다.
10. 프로토타입에서는 미니게임, PvP, 가챠, 복잡한 경제 시스템을 만들지 않는다.

# 1. 프로젝트 정의

## 1.1 한 줄 정의

> **사용자가 현실에서 완료한 일을 바탕으로 작은 정령의 하루가 만들어지고, 그 하루들이 쌓여 정령의 생활 방식·관심사·진로·최종 모습이 결정되는 동행형 생활 시뮬레이션.**

## 1.2 이 게임에서 사용자가 반복해서 확인하는 것

사용자는 게임에 들어올 때 다음이 궁금해야 한다.

- 오늘 정령은 무엇을 하고 있나?
- 내가 오늘 한 일이 정령의 하루에서는 어떻게 바뀌었나?
- 이 정령은 무엇을 좋아하게 되고 있나?
- 지난 정령과 이번 정령은 왜 다르게 행동하나?
- 이 정령은 결국 어떤 모습으로 자라고 어떤 길을 선택할까?

이 다섯 질문이 게임의 주요 콘텐츠를 결정한다.

## 1.3 게임의 역할과 TODO 앱의 역할

| 영역 | 역할 |
|---|---|
| TODO 앱 | 할 일·루틴 생성, 일정 관리, 완료 처리, 현실 기록 보관 |
| 정령 게임 | 현실 기록을 정령의 생활로 바꾸고, 행동·성장·진로·독립 과정을 보여줌 |
| 서버/공용 데이터 | 완료 기록, 정령 상태, 정수, 인벤토리, 동행 기록 저장 |

### TODO 입력 부담을 늘리지 않는다

게임 때문에 사용자가 TODO를 더 복잡하게 입력하면 안 된다.

사용자가 입력하는 정보는 다음 정도로 제한한다.

- 할 일 제목
- 9개 상위 카테고리 중 하나
- 날짜/시간/반복 등 원래 TODO 기능에 필요한 값

세부 분류와 정령 행동 변환은 시스템이 처리한다.

# 2. 핵심 플레이 구조

## 2.1 하루 루프

```text
현실에서 TODO / 루틴 완료
        ↓
완료된 활동을 하루 기록으로 정리
        ↓
정령의 기질 + 최근 생활 + 현재 성장 상태와 결합
        ↓
정령의 장소 / 행동 / 작은 사건 결정
        ↓
게임 진입
        ↓
정령이 실제로 행동하고 있는 모습 확인
        ↓
오늘의 기록에서 현실의 나 / 정령의 하루 확인
        ↓
필요하면 선물 / 여행 / 꾸미기로 가볍게 개입
        ↓
다음 현실 생활로 복귀
```

### 목표 플레이 시간

- 게임 확인만 할 때: **20초~1분**
- 선물·여행 등을 사용할 때: **1~3분**
- 성장·독립 이벤트: **2~5분**

게임 안에서 다시 노동하게 만들지 않는다.

## 2.2 한 정령의 사이클

```text
어린 정령과 만남
    ↓
새로운 생활에 적응
    ↓
다양한 행동을 경험
    ↓
자주 찾는 장소와 좋아하는 행동이 생김
    ↓
특정 활동을 자기 방식으로 이어가기 시작
    ↓
진로의 방향이 보이기 시작
    ↓
성체 성장
    ↓
함께한 기록 회고
    ↓
사용자가 정식 이름을 지어줌
    ↓
이름을 가진 상태로 마지막 동행
    ↓
정령 독립
    ↓
편지 / 방문 / 동행 기록 유지
    ↓
정령의 알 3~5개 중 하나 선택
    ↓
새로운 어린 정령
```

## 2.3 장기 루프

장기적으로 사용자의 계정에는 다음이 쌓인다.

- 함께했던 정령 목록
- 각 정령에게 지어준 이름
- 정령별 기질
- 자주 했던 행동과 장소
- 최종 성체 모습
- 최종 진로
- 함께한 기간의 현실 TODO 기록
- 정령의 하루 기록
- 정령이 보낸 편지
- 여행에서 얻은 발견물
- 정령의 집과 숲에 남은 장식

장기 목표는 `정령을 많이 모은다` 하나가 아니다.

> **내 현실 기록과 함께 정령들의 서로 다른 삶이 계정에 쌓이는 것**이 장기 플레이의 중심이다.

# 3. 세계 구조

## 3.1 프로토타입의 세계 범위

프로토타입에서는 넓은 마을 전체를 만들지 않는다.

**정령의 집 + 작은 앞마당** 하나를 메인 생활 공간으로 사용한다.

이 공간 안에 5개의 대표 행동 장소를 둔다.

| 장소 | 대표 행동 | 예시 |
|---|---|---|
| 책장 / 작은 책상 | 학습·기록 | 책 읽기, 기록하기, 자료 살펴보기 |
| 공작대 | 업무·제작 | 만들기, 고치기, 정리하기 |
| 앞마당 / 숲길 입구 | 건강·탐색 | 걷기, 뛰기, 주변 관찰 |
| 티테이블 | 교류 | 친구와 차 마시기, 대화하기 |
| 침상 / 쉼터 | 휴식 | 낮잠, 음악 듣기, 멍하니 있기 |

### 프로토타입 이후 확장 가능 장소

- 숲 도서관
- 작은 공방
- 마을 광장
- 바람 들판
- 연못
- 여행 지역
- 시장
- 정령 학교

확장 장소를 지금 구현하지 않는다. 프로토타입에서 `정령이 생활하는 모습을 보는 것이 실제로 재미있는가`를 먼저 확인한다.

## 3.2 세계 표현 원칙

정령의 집은 단순 배경 이미지가 아니라 **행동이 발생하는 무대**다.

예를 들어 책장을 설치했거나 책장 콘텐츠가 열려 있다면 다음 행동이 가능하다.

- 책 고르기
- 책 읽기
- 책 정리하기
- 기록하기

티테이블이 있다면 다음 행동이 가능하다.

- 혼자 차 마시기
- 친구 초대하기
- 간식 먹기

따라서 장식은 장기적으로 `예쁜 배경`뿐 아니라 **새 행동을 추가하는 생활 요소**로 확장할 수 있다.

# 4. 현실 TODO를 정령의 하루로 바꾸는 규칙

## 4.1 사용자 카테고리 9종

사용자가 TODO 생성 시 직접 선택하는 상위 카테고리는 다음과 같다.

1. 업무 / 학업 / 커리어 / 공부
2. 건강
3. 생활
4. 인간관계 / 약속
5. 자기계발
6. 취미
7. 휴식 / 마인드
8. 자산
9. 경제

## 4.2 세부 분류는 사용자에게 요구하지 않는다

예를 들어 사용자가 다음 TODO를 등록했다.

```text
제목: 헬스장 1시간
카테고리: 건강
```

시스템 내부에서는 다음처럼 해석할 수 있다.

```text
건강
→ 운동
→ 정령 행동 후보: 훈련 / 산책 / 뛰기
```

사용자가 `운동`이라는 세부 분류를 추가로 선택할 필요는 없다.

### 분류 우선순위

1. 사용자가 과거에 같은/비슷한 TODO의 분류를 수정한 기록
2. 반복 루틴에 저장된 기존 분류
3. 제목 키워드
4. 상위 카테고리 안의 세부 분류 규칙
5. 상위 카테고리 기본 행동 후보

분류가 애매하더라도 TODO 저장을 막지 않는다.

## 4.3 카테고리별 대표 정령 행동

| 현실 카테고리 | 정령 세계의 대표 표현 |
|---|---|
| 업무/학업/커리어/공부 | 책 읽기, 기록 정리, 공방 일, 연구, 연습 |
| 건강 | 산책, 달리기, 스트레칭, 몸 돌보기 |
| 생활 | 청소, 요리, 정리, 물건 수리, 화분 돌보기 |
| 인간관계/약속 | 친구 만나기, 차 마시기, 편지 보내기, 다른 정령 돕기 |
| 자기계발 | 새로운 책, 새로운 기술 연습, 하루 기록, 목표 정리 |
| 취미 | 그림, 음악, 수집, 놀이, 가벼운 탐색 |
| 휴식/마인드 | 낮잠, 명상, 구름 보기, 산책, 음악 듣기 |
| 자산 | 창고 정리, 생활 장부, 필요한 물건 계획하기 |
| 경제 | 시장 소식 읽기, 상업 공부, 마을 거래 상황 살펴보기 |

### 주의

`현실 행동 → 정령 행동`은 그대로 복사하지 않는다.

예:

```text
현실: 버그 수정
정령: 공작대에서 고장 난 작은 도구를 수리함
```

```text
현실: 주식 시황 확인
정령: 마을 장터에서 최근 물품 가격을 기록함
```

정령 세계의 판타지 표현으로 번역한다.

# 5. 정령의 선천 기질

## 5.1 기본 규칙

한 정령은 태어날 때 **2~3개의 기질**을 가진다.

프로토타입에서는 다음 8개 중 조합한다.

| 기질 | 행동 특징 예시 |
|---|---|
| 호기심 많음 | 새로운 장소·물건·행동을 먼저 시도함 |
| 느긋함 | 활동 사이 휴식 비율이 높고 행동 속도가 여유로움 |
| 활동적 | 산책·탐색·움직이는 행동을 선호함 |
| 사교적 | 혼자보다 다른 정령과 함께하는 행동을 자주 선택함 |
| 신중함 | 익숙한 행동을 반복하고 새로운 행동 전 확인 동작이 많음 |
| 꼼꼼함 | 정리·기록·완성 행동을 끝까지 이어가는 경향 |
| 장난기 많음 | 같은 장소에서도 놀이 행동이나 예상 밖 반응이 자주 나옴 |
| 독립적 | 사용자 기록을 그대로 따라가기보다 자기 행동을 이어가는 비율이 높음 |

## 5.2 기질의 역할

기질은 정령의 능력치 보너스가 아니다.

기질은 같은 하루 기록을 **어떻게 표현할지** 바꾸는 값이다.

예를 들어 사용자가 공부 관련 TODO를 많이 완료했다.

### 호기심 + 활동적

- 책을 읽다가 직접 숲으로 확인하러 감
- 지도와 실제 장소를 비교함

### 신중함 + 꼼꼼함

- 책을 오래 읽음
- 읽은 내용을 다시 정리함
- 기록을 남김

### 사교적 + 호기심

- 다른 정령에게 물어봄
- 배운 내용을 함께 이야기함

사용자의 현실 기록은 같아도 정령의 하루는 다르게 보일 수 있다.

## 5.3 사용자에게 기질을 숫자로 보여주지 않는다

금지 예시:

```text
호기심 82
사교성 55
```

허용 예시:

- “새로운 걸 보면 그냥 지나치지 못하는 것 같다.”
- “혼자 있을 때보다 누군가와 함께 있을 때 더 활발하다.”

# 6. 정령의 하루 시뮬레이션

## 6.1 자동 행동과 사용자 개입 비율

목표 비율:

- **70~80%:** 정령이 스스로 결정
- **20~30%:** 사용자가 가끔 개입

사용자가 매일 정령의 시간표를 만들지 않는다.

## 6.2 하루 행동 선택에 사용하는 값

정령의 행동은 다음 네 요소를 함께 본다.

1. 오늘 사용자가 완료한 활동
2. 최근 며칠 동안 반복된 생활 패턴
3. 정령의 선천 기질
4. 정령이 지금까지 자주 선택한 행동·장소·진행 중인 활동

행동 선택 순서는 다음과 같다.

```text
오늘 완료한 TODO를 행동 후보로 만든다.
        ↓
정령의 기질에 잘 맞는 후보의 우선순위를 조금 올린다.
        ↓
최근 너무 자주 나온 행동은 우선순위를 낮춘다.
        ↓
현재 성장 단계에서 아직 경험이 부족한 행동을 일부 섞는다.
        ↓
오늘 대표 행동 1개 + 보조 행동 0~2개를 선택한다.
```

프로토타입에서는 복잡한 AI가 필요 없다. **가중치 + 규칙 + 고정 시드 랜덤**으로 충분하다.

## 6.3 대표 행동과 보조 행동

하루 기록에 TODO가 여러 개 있더라도 메인 화면에서 모든 행동을 동시에 보여주지 않는다.

- 대표 행동: 메인 화면에서 현재 정령이 하고 있는 행동 1개
- 보조 행동: `오늘의 기록`에 텍스트 또는 작은 이미지로 남는 행동 0~2개

예:

```text
오늘 사용자
- 기획서 수정
- 30분 산책
- 친구와 저녁
- 독서

대표 행동
- 공작대에서 기록 지도를 정리함

보조 행동
- 숲길을 걸음
- 친구와 차를 마심
- 밤에 책을 읽음
```

## 6.4 같은 TODO라도 매일 같은 장면을 만들지 않는다

예를 들어 `독서`는 다음 중 하나로 변형할 수 있다.

- 책상에서 책 읽기
- 바닥에 엎드려 그림책 보기
- 창가에서 책 읽기
- 읽은 내용을 수첩에 적기
- 다른 정령에게 책 내용 보여주기

같은 기본 애니메이션과 소품을 재활용하면서 장면의 느낌을 바꾼다.

# 7. 성장 구조

## 7.1 성장 기간

정확한 달력 28일을 사용하지 않는다.

프로토타입 목표:

- 빠른 성장: 약 4주
- 평균 성장: 약 5주
- 느린 성장: 약 6주

여기서 `주`는 달력 경과만 의미하지 않는다. 사용자가 실제로 TODO 또는 루틴을 완료해 **정령에게 생활 기록이 생긴 날**을 중심으로 성장한다.

며칠 쉬었다고 정령이 퇴보하지 않는다.

## 7.2 성장 단계

날짜마다 자동으로 진화시키지 않는다. 아래 단계는 **정령의 생활이 바뀌는 상태**를 나타낸다.

### 단계 A. 첫 만남

정령이 새로운 공간과 사용자를 익히는 단계.

특징:

- 단순 행동이 많음
- 사용자 기록을 비교적 직접적으로 따라감
- 기질을 쉽게 관찰할 수 있는 반응이 나옴
- 행동 장소가 제한적

### 단계 B. 생활 적응

정령이 집과 주변 공간을 익힌 단계.

특징:

- 행동 장소가 늘어남
- 같은 활동을 기질에 맞게 다르게 표현하기 시작
- 자주 선택하는 행동이 조금씩 나타남

### 단계 C. 관심사 발견

정령이 특정 행동과 장소를 반복해서 찾기 시작하는 단계.

특징:

- 좋아하는 장소가 생김
- 같은 현실 기록을 자신이 좋아하는 방식으로 바꾸는 비율 증가
- 사용자에게 “요즘 ○○를 자주 한다.” 수준의 힌트 제공

### 단계 D. 자기 방식 형성

정령이 단순히 사용자를 따라 하지 않고 자기 활동을 이어가기 시작한다.

특징:

- 며칠에 걸쳐 이어지는 작은 활동이 생길 수 있음
- 예: 지도 만들기, 화분 키우기, 책 정리하기
- 진로 후보가 내부적으로 좁혀지기 시작

### 단계 E. 진로 준비

정령이 성체가 된 뒤 하고 싶은 일을 준비하는 단계.

특징:

- 특정 활동을 스스로 이어감
- 대사와 행동에서 미래 방향의 힌트가 보임
- 최종 모습 일부가 외형에 나타나기 시작

### 단계 F. 성체

생활 기록·기질·자주 한 행동을 바탕으로 성체 모습과 진로가 결정된다.

## 7.3 단계 전환 기준

단계를 단순 `n일째`로 바꾸지 않는다.

내부에서는 다음을 함께 확인한다.

- 현재 단계에서 필요한 최소 활동일을 지났는가?
- 서로 다른 행동을 충분히 경험했는가?
- 특정 행동이나 장소에 반복 패턴이 생겼는가?
- 현재 단계에서 보여줘야 할 핵심 이벤트를 최소 1회 확인했는가?

최대 활동 기간을 넘겼는데도 조건이 부족하면 현재 기록 중 가장 강한 패턴을 사용해 다음 단계로 넘어간다.

**새로운 관심사를 시스템이 억지로 만들어내지는 않는다.**

## 7.4 사용자 UI에는 정확한 진행률을 보여주지 않는다

금지:

```text
성장률 73%
성체까지 11일
```

허용:

- “새로운 집에 적응하고 있어요.”
- “좋아하는 일이 조금씩 생기는 것 같아요.”
- “요즘 스스로 이어가는 일이 있어요.”
- “자기 길을 찾기 시작한 것 같아요.”

# 8. 진로 시스템

## 8.1 진로의 목적

성체 진화는 단순히 색과 외형이 바뀌는 이벤트가 아니다.

정령이 지금까지 살아온 방식에 따라 **성체 모습 + 앞으로 살아갈 진로**가 함께 결정된다.

## 8.2 진로 판정에 사용하는 요소

우선순위는 다음과 같다.

1. 정령이 실제로 반복한 행동과 장소
2. 정령이 오래 이어간 활동
3. 선천 기질
4. 사용자의 전체 생활 기록
5. 여행이나 특별 사건에서 얻은 보조 경험

사용자의 카테고리 하나만으로 진로를 바로 결정하지 않는다.

예:

```text
사용자에게 공부 기록이 많음

정령 A
- 기록을 자주 남김
- 꼼꼼함
→ 기록가

정령 B
- 다른 정령과 함께 공부하는 행동이 많음
- 사교적
→ 교사

정령 C
- 책에서 본 장소를 직접 확인하는 행동이 많음
- 활동적 + 호기심
→ 탐방 연구가
```

## 8.3 프로토타입 진로 수

프로토타입에서는 **3개 진로**만 완성도 있게 제작한다.

권장 예시:

| 진로 | 주요 생활 모습 | 대표 소품 |
|---|---|---|
| 기록가 | 읽기, 정리, 관찰, 기록 | 수첩, 펜, 작은 가방 |
| 탐방가 | 산책, 조사, 새로운 장소 탐색 | 지도, 망원경, 배낭 |
| 공예가 | 만들기, 수리, 그림, 생활 작업 | 공구, 앞치마, 작은 작품 |

이 3종은 프로토타입 검증용이다. 정식 버전에서는 교사, 정원사, 요리사, 음악가, 상인, 치유사, 안내자 등으로 확장할 수 있다.

# 9. 오늘의 기록

## 9.1 역할

`오늘의 기록`은 단순 보상 팝업이 아니다.

> **사용자의 현실 하루와 정령의 하루를 한 화면에 남기는 핵심 기록 기능**이다.

## 9.2 기본 구조

```text
8월 31일

오늘 나는
────────────────────
기획서 수정
30분 산책
친구와 저녁
독서

오늘 정령은
────────────────────
공작대에서 기록 지도를 정리했다.
정원 주변을 천천히 걸었다.
친구와 차를 마셨다.
밤에는 창가에서 책을 읽었다.
```

### 반드시 지킬 것

- 현실 TODO의 이름을 확인할 수 있다.
- 그 TODO가 정령 세계에서 어떻게 바뀌었는지도 확인할 수 있다.
- 카테고리별 점수나 성장 수치 분석 화면으로 만들지 않는다.
- 하루가 지날수록 기록이 계속 쌓인다.

## 9.3 메인 화면의 짧은 요약 카드

게임 진입 시 화면을 막지 않는 작은 카드로만 먼저 보여준다.

표시 정보:

- `오늘 함께한 기록`
- 완료 개수
- 획득 정수

동작:

- 상단 또는 하단에서 슬라이드 인
- 약 1~2초 후 접힘
- 탭하면 즉시 닫힘 또는 상세 `오늘의 기록` 열기
- 정령을 가리지 않음

## 9.4 기록 보관

프로토타입에서는 다음 정도만 지원한다.

- 오늘 기록
- 이전 날짜 목록
- 특정 날짜 상세 보기

월간 AI 요약, 자동 회고, SNS 공유는 프로토타입에서 제외한다.

# 10. 사용자의 개입

## 10.1 개입의 원칙

사용자의 개입은 정령의 하루를 완전히 지휘하는 기능이 아니다.

개입은 다음 목적을 가진다.

- 정령에게 새로운 물건을 경험하게 함
- 새로운 장소나 사건을 열어줌
- 생활 공간을 조금씩 바꿈
- 정령의 반응 차이를 관찰함

## 10.2 선물

프로토타입 선물은 6종 정도로 제한한다.

예:

- 작은 책
- 따뜻한 담요
- 그림 도구
- 작은 화분
- 나무 열매 차
- 반짝이는 돌

선물은 정확한 성장 수치를 올리지 않는다.

예:

```text
작은 책 사용
→ 책 관련 행동 후보 추가
→ 정령 기질에 따라 반응 차이 발생
```

호기심 많은 정령은 바로 펼쳐볼 수 있고, 활동적인 정령은 잠깐 보고 다른 행동을 할 수 있다.

## 10.3 여행

프로토타입에서는 여행지 1곳만 만든다.

기본 흐름:

```text
여행 선택
→ 준비물 3개 중 하나 선택
→ 정수 소비
→ 일정 시간 경과
→ 귀환
→ 짧은 사건 + 발견물 + 기록
```

권장 프로토타입 값:

- 여행 비용: 정수 40
- 여행 시간: 4시간
- 동시 여행: 1개
- 실패 없음
- 늦게 회수해도 보상 감소 없음

준비물은 결과 방향만 바꾼다.

- 작은 도시락: 교류 사건 증가
- 빈 가방: 발견물 사건 증가
- 관찰 수첩: 기록·탐색 사건 증가

## 10.4 꾸미기

프로토타입에서 자유 배치는 만들지 않는다.

**고정 슬롯형 꾸미기**를 사용한다.

예:

- 책장 슬롯
- 공작대 슬롯
- 테이블 슬롯
- 화분 슬롯
- 쉼터 슬롯

일부 장식은 나중에 행동 후보를 추가할 수 있다.

# 11. 정수 경제

## 11.1 정수의 역할

정수는 정령 성장 경험치가 아니다.

> **사용자가 정령의 생활 세계에 가볍게 개입하기 위한 재화**다.

사용처:

- 선물
- 여행
- 꾸미기

## 11.2 획득 규칙

TODO를 잘게 쪼개 정수를 파밍하는 것을 막기 위해 하루 완료 개수를 구간제로 처리한다.

| 하루 완료 TODO | 그날 누적 정수 보상 |
|---:|---:|
| 0개 | 0 |
| 1개 | 10 |
| 2~3개 | 18 |
| 4개 이상 | 25 |

규칙:

- 하루 최대 25
- 같은 TODO를 완료 → 해제 → 재완료해도 중복 지급하지 않음
- 그날 이미 받은 최고 보상 구간을 저장

## 11.3 정수로 구매하면 안 되는 것

- 성장 단계
- 성체 진로 변경
- 정령 기질 변경
- 행동 강제 재추첨
- 오늘의 기록 열람
- 실패 복구
- TODO 보상 배수

현실 행동의 결과를 돈이나 정수로 덮어쓰지 않는다.

# 12. 성체, 이름, 독립

## 12.1 성체 성장

성체 조건을 만족하면 바로 정령을 떠나보내지 않는다.

순서는 다음과 같다.

```text
성체 모습 공개
→ 진로 공개
→ 함께한 기록 회고
→ 사용자에게 이름 짓기 요청
→ 이름 확정
→ 이름을 가진 상태로 마지막 동행
→ 독립 이벤트
```

## 12.2 이름 짓기

육성 중에는 정식 고유명을 사용하지 않는다.

UI에서는 다음과 같은 호칭을 사용한다.

- 작은 정령
- 이 아이
- 어린 정령

성체가 된 뒤 떠나기 전에 사용자가 처음으로 정식 이름을 지어준다.

예시 문구:

> 이 아이와 함께한 시간이 끝나가고 있습니다.  
> 떠나기 전에, 앞으로 기억할 이름을 하나 선물해 주세요.

이름을 확정하면 과거 기록에서도 해당 정령의 이름을 사용한다.

## 12.3 마지막 동행

이름을 지은 직후 바로 사라지지 않는다.

최소 한 번은 정식 이름을 가진 상태로 메인 화면에 등장한다.

이 기간에 사용할 수 있는 콘텐츠:

- 이름을 확인하는 짧은 대사
- 마지막 평소 행동
- 독립을 준비하는 작은 연출

## 12.4 독립

정령이 떠나는 것은 실패나 삭제가 아니다.

정령은 자신이 선택한 진로를 따라 숲 밖의 삶을 시작한다.

독립 이후 유지:

- 동행 기록
- 이름
- 성체 모습
- 진로
- 편지
- 방문 이벤트

프로토타입에서는 편지 실제 수신 시스템까지 만들지 않아도 된다. `이후 편지를 받을 수 있다`는 슬롯/목록 구조까지만 준비해도 된다.

# 13. 다음 정령과 알 선택

## 13.1 첫 정령

첫 번째 정령은 튜토리얼용으로 고정 제공한다.

목적:

- 사용자가 시스템을 이해하게 함
- 기질·행동·기록·성장·성체·이름·독립을 한 번 경험하게 함

## 13.2 다음 정령

첫 정령이 독립할 때 **정령의 알 3~5개**를 남긴다.

세계관상 이 알은 생물학적인 자식이 아니다.

> 함께 지낸 시간과 정령이 남긴 힘이 숲에서 작은 알의 형태로 굳어진 것.

프로토타입에서는 3개 알만 제공한다.

## 13.3 알 선택 UI

정답을 보여주지 않는다.

나쁜 예:

```text
활동형 알
활동성 +20
```

좋은 예:

- “안에서 무언가 자주 움직인다.”
- “손에 올리면 포근한 온기가 느껴진다.”
- “가끔 표면의 무늬가 달라진다.”

사용자는 힌트를 보고 하나를 고른다.

## 13.4 알과 기질

선택한 알에 따라 다음 정령의 기질 후보가 조금 달라질 수 있다.

프로토타입에서는 구현을 단순하게 한다.

- 알 A: 활동적 관련 기질 가중치 높음
- 알 B: 느긋함/신중함 가중치 높음
- 알 C: 호기심/사교성 가중치 높음

# 18. 하루 처리 순서

주니어 개발자가 구현할 때 다음 순서를 기본으로 사용한다.

## 18.1 TODO 완료 시

```text
1. TODO 완료 상태 저장
2. 해당 TODO 분류 결과 확인
3. 날짜별 완료 수 갱신
4. 날짜별 정수 보상 구간 계산
5. 이전에 받은 보상보다 높아졌다면 차액만 지급
6. DailyCompanionRecord의 입력 데이터 갱신
```

## 18.2 게임 진입 시

```text
1. 오늘 DailyCompanionRecord 확인
2. 아직 오늘 정령 행동을 결정하지 않았다면 행동 결정
3. 같은 날짜에는 같은 결과를 유지
4. 메인 화면에서 primaryAction 재생
5. 확인하지 않은 정수 보상이 있으면 짧은 카드 표시
```

## 18.3 날짜가 끝날 때 또는 다음 날 첫 진입 시

```text
1. 그날의 정령 행동 기록 확정
2. 정령의 선호 행동/장소 누적
3. 성장 단계 전환 조건 확인
4. 진로 후보 내부 기록 갱신
5. 해당 날짜 기록을 수정 불가 상태로 확정
```

# 22. 프로토타입 검증 기준

프로토타입은 기능 개수로 성공을 판단하지 않는다.

## 22.1 반드시 확인할 질문

### Q1. TODO와 정령 행동 연결을 사용자가 이해하는가?

테스트 후 사용자가 다음을 설명할 수 있어야 한다.

> “내가 오늘 한 일들이 이 아이가 오늘 뭘 하는지에 영향을 주는 것 같다.”

목표: 테스트 사용자 80% 이상.

### Q2. 같은 정령을 다시 확인할 이유가 있는가?

사용자에게 묻는다.

- 내일 어떤 행동을 할지 궁금한가?
- 다른 기질의 정령이 어떻게 행동할지 궁금한가?

목표: 긍정 응답 70% 이상.

### Q3. 오늘의 기록이 일반 TODO 기록과 다른 가치가 있는가?

사용자가 현실 TODO와 정령의 하루가 함께 남는 기능을 다시 보고 싶다고 느끼는지 확인한다.

목표: 긍정 응답 70% 이상.

### Q4. 성체 결과가 납득되는가?

성체 결과를 본 뒤 사용자가 다음 질문에 답할 수 있어야 한다.

> “왜 이 정령이 이 진로가 됐는지 이해되나요?”

목표: 80% 이상 `그렇다`.

### Q5. 이름 짓기와 독립 이후 다음 정령을 시작하고 싶은가?

목표: 60% 이상.

## 22.2 실패 신호

다음 반응이 반복되면 기획을 다시 수정한다.

- “그냥 TODO 체크하면 캐릭터가 랜덤 행동하는 것 같다.”
- “왜 이런 진로가 됐는지 모르겠다.”
- “정수가 왜 필요한지 모르겠다.”
- “게임에서 내가 할 게 너무 많다.”
- “정령이 바뀌어도 차이를 모르겠다.”
- “오늘의 기록을 굳이 다시 볼 이유가 없다.”
- “성체가 되기까지 너무 오래 걸린다.”

# 23. QA 체크리스트

## TODO / 기록

- [ ] TODO 완료 0개인 날에도 오류 없이 처리된다.
- [ ] TODO 1개만 완료해도 정령 행동이 생성된다.
- [ ] TODO를 20개 완료해도 정수는 일일 상한을 넘지 않는다.
- [ ] 완료 → 해제 → 재완료해도 정수가 중복 지급되지 않는다.
- [ ] 현실 TODO 제목과 정령 행동이 오늘의 기록에 연결되어 있다.

## 정령 행동

- [ ] 같은 날짜를 다시 열어도 정령의 대표 행동이 바뀌지 않는다.
- [ ] 기질이 다른 정령은 같은 입력에서 다른 행동 후보를 선택할 수 있다.
- [ ] 최근 같은 행동이 반복되면 다른 표현이 나올 수 있다.
- [ ] 없는 애니메이션 때문에 진행이 막히지 않는다.

## 성장

- [ ] 며칠 접속하지 않아도 성장 상태가 감소하지 않는다.
- [ ] 성장 단계 전환이 특정 달력 날짜에만 의존하지 않는다.
- [ ] 최대 성장 기간을 넘으면 다음 단계로 정상 전환된다.
- [ ] 성체 진로 판정 결과가 같은 저장 데이터에서 바뀌지 않는다.

## 이름 / 독립 / 다음 정령

- [ ] 이름 입력 전 과거 기록이 깨지지 않는다.
- [ ] 이름 입력 후 과거 기록에도 이름이 정상 표시된다.
- [ ] 이름을 가진 상태의 마지막 동행 화면이 존재한다.
- [ ] 독립 후에도 이전 정령 기록을 열 수 있다.
- [ ] 알 선택 후 새 정령 상태가 정상 생성된다.

# 24. 프로토타입 완료 정의

프로토타입은 다음 흐름이 처음부터 끝까지 끊김 없이 동작하면 기능적으로 완료다.

```text
첫 정령 제공
↓
현실 TODO 완료
↓
정령의 하루 생성
↓
메인 화면에서 행동 관찰
↓
오늘의 기록 확인
↓
여러 활동일 반복
↓
성장 단계 변화
↓
진로 형성
↓
성체
↓
함께한 기록 회고
↓
사용자가 이름 짓기
↓
마지막 동행
↓
독립
↓
알 3개 중 하나 선택
↓
두 번째 정령 시작
```

이 흐름이 동작하기 전에는 미니게임, 가챠, 소셜 기능, 대규모 꾸미기 시스템을 추가하지 않는다.

# 25. 최종 기획 기준

개발 중 기능을 추가할지 고민될 때 아래 질문을 순서대로 확인한다.

1. 이 기능이 사용자의 현실 하루를 정령의 삶으로 바꾸는 데 필요한가?
2. 이 기능으로 정령마다 다른 생활 방식이 더 잘 보이는가?
3. 이 기능이 오늘의 기록 또는 한 정령의 성장 이야기를 더 풍부하게 만드는가?
4. 사용자가 정령의 일정까지 관리해야 하는 부담을 만들지는 않는가?
5. 현실 TODO를 게임 보상을 위해 억지로 만들게 하지는 않는가?

1~3 중 하나도 충족하지 못하거나, 4~5에 문제가 있다면 프로토타입에서 제외한다.

> **이 프로젝트의 중심은 “할 일을 하면 보상을 받는다”가 아니다.**  
> **사용자가 실제로 살아낸 하루가 작은 정령의 또 다른 하루가 되고, 그 두 기록이 함께 쌓여 한 정령의 삶을 완성하는 것이 핵심이다.**
