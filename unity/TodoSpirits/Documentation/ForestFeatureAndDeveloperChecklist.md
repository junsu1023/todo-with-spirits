# 숲 화면 기능 안내 및 동료 개발자 검증 체크리스트

확인일: 2026-09-18 · 대상: Unity `TodoSpirits`의 현재 숲 화면 · 상태: 현재 구현 안내와 재검증 체크리스트

> 이 문서는 **현재 구현**을 설명한다. 목표 경험과의 차이 및 구현 수락 기준은 [정령의 하루 상세 기획 v4](ForestDailyExperiencePlanV4.md)를 따른다.

## 범위와 읽는 법

- **현재 UI**는 `00_Boot` → `01_Main` → `PF_UI_ForestApp` 흐름이다. 숲을 기본 화면으로 열고, 오늘 기록은 읽기 전용 시트, 앨범은 별도 화면으로 연다.
- **Android 연결 코드**는 기존 사용자 프로필·달력 API와 `ForestUnityActivity`를 통해 계정 세션과 오늘 전체 목록을 보낸다. 실제 호스트 앱 빌드·실기기 실행 성공은 별도 검증 사항이다. 연결 전에는 확인 대기 상태를 표시하며 정상적인 일정 0개와 구별한다.
- 아래 `구현`은 소스에 존재한다는 뜻이며, `[ ]`는 동료가 새 환경에서 실행할 항목이다. 실행 근거는 [현재 수락 기록](ForestPrototypeAcceptance.md)과 `Validation/ForestPrototype`에서 확인한다. EditMode 통과가 실기기 통합 성공을 뜻하지는 않는다.
- 사용자 첨부 설치·구현 프롬프트와 컨셉 이미지는 요구/시각 참고 자료다. 실제 동작 판단에는 현재 씬·프리팹·코드를 우선했다.
- WebGL은 `ForestWebPersistenceBuild` 후처리가 HTML의 자동 영구 저장을 활성화한다. 실제 재접속에서 예시 이름·선택·정수와 당일 확인 상태를 검사한 기록은 `Validation/ForestPrototype/web-browser-smoke.md`에 있다. 브라우저 저장 차단·할당량 초과·모바일 브라우저는 별도 재검증한다.

## 검증 준비

1. Unity 6000.3.16f1로 프로젝트를 열고 `00_Boot`에서 시작한다. 개인 저장을 보호하려면 Play 전에 `TodoSpirits > Art Kit > 4 - Use Isolated QA Save`를 실행한다. 종료 후 `5 - Clear Isolated QA Save`로 QA 경로를 해제한다.
2. 실제 TODO 연동은 [Android 호스트 연결 문서](ForestAndroidHostIntegration.md)를 따라 Unity 라이브러리를 export하고 호스트를 빌드한다. Unity 단독 Play는 예시 체험 또는 명시적 브리지 입력으로 검증한다. 예시 입력의 성공을 실제 계정 연동 성공으로 기록하지 않는다.
3. 각 항목의 실제 결과, 기기/OS, 사용한 계정·날짜·데이터 개수, Console/로그, 재현 절차를 기록한다. 개발용 날짜 이동은 격리 저장에서만 사용한다.

## 동료 개발자 체크리스트

### 빠르게 체험하는 순서

1. 격리 QA 저장을 선택하고 `00_Boot`를 실행한다. 첫 팝업의 `예시 하루 체험하기` 또는 설정의 `예시 하루 체험` → `별도의 예시 숲 열기`를 누른다.
2. 원래 일정 → 정령의 하루 → 획득까지 스크롤하고 `숲에서 정령 만나기`로 닫는다. 이름은 입력하거나 나중에 정한다. 메인 정령을 반복해서 눌러 상황 대사를 읽는다.
3. 메인의 이야기 초대에서 A/B 중 하나를 선택한다. 결과 문장, 숲에 남은 소품, 앨범의 그날 장면을 비교한다.
4. `체험 안내`에서 세 입력 유형과 완료 0/1/2/4개를 바꾼다. `다음 예시 날짜로 · 하루 이어 보기`로 활동일을 쌓으며 4·7일 이야기를 선택하고 21일 성체를 확인한다. 첫 선택 이후 이야기 계열은 유지되므로 다른 계열 전체 비교에는 다른 격리 예시 저장을 사용한다.
5. 성체의 설정에서 `다음 동행 이야기`를 열어 계속 함께 지내거나 배웅한다. 새 알을 고른 뒤 첫 이름, 실제 당일 유지, 이전 앨범을 확인한다. 체험이 끝나면 `내 숲으로 돌아가기`를 누르고 Play 종료 후 QA 저장 경로를 해제한다.

### Unity 화면·리소스

- [ ] `00_Boot` 진입 후 `01_Main`의 숲이 열리고 Console Error가 없다.
- [ ] 숲의 정령·정수·설정·앨범·오늘 시트·돌보기·꾸미기·나들이를 각각 열고 닫을 수 있다. 인게임 닫기 버튼의 모달 닫기/숲 복귀를 확인한다. Android 시스템 뒤로 가기는 현재 `ForestUnityActivity` 구현대로 Unity unload→Activity 종료→Today 복귀하는지 실기기에서 따로 확인한다(현재 실기기 NOT RUN).
- [ ] 360×640, 1080×2340, 1366×768에서 안전 영역, 버튼 터치 영역, 긴 제목·긴 한국어 대사, 스크롤·모달이 겹치거나 잘리지 않는다.
- [ ] `동작 줄이기`를 켠 뒤 재시작해 유지와 움직임 변화를 확인한다.
- [ ] 관찰/활동 기질의 같은 활동·같은 터치를 비교한다. 몸·그림자·소품이 함께 움직이고 터치 연타로 계속 부풀거나 떠다니지 않는다.
- [ ] 어린/스카프/성체 3단계가 메인·팝업·편지에 맞게 표시되고 앨범의 이전 단계가 바뀌지 않는다. 독서 소품 때문에 성장한 정령이 어린 그림으로 되돌아가지 않는다.
- [ ] `TodoSpirits > Art Kit > 2 - Validate Imported Resources`에서 오류 0개를 확인하고 Atlas 패킹 및 기기 GPU 메모리·프레임을 측정한다.
- [ ] 디자인 검수에서 분홍 정령과 컨셉 새싹 정령의 차이, 가로 화면 여백을 명시적으로 승인/수정한다.

### TODO·날짜·성장

- [ ] 연결 전 빈 오늘 시트가 정상 표시되며, 네트워크 실패를 `일정 0개`로 오인하지 않는다.
- [ ] 호스트가 0~50개의 **전체 오늘 목록**을 보내면 제목·카테고리·완료 표시가 시트에 정확히 나타나고, 루틴/일정 구분은 내부 `isHabit`으로 반영된다. 숲에서는 체크와 수정이 불가능하다.
- [ ] 일정 생성·수정·삭제·완료·완료 취소 후 새 스냅샷으로 오늘 시트와 정령 대사/기록이 갱신된다. 같은 스냅샷 재전송은 중복 보상을 만들지 않는다.
- [ ] 다른 계정/날짜, 중복 ID, 알 수 없는 카테고리, 255자 초과 제목, 50개 초과 새 목록은 거부되고 기존 기록이 보존된다. 낮은 `revision`은 무시한다. 같은 revision은 기존 사실을 재적용하지 않고 마지막 확인 시각만 갱신하므로 발신자는 내용이 바뀔 때 반드시 revision을 올린다.
- [ ] 반복 루틴의 날짜별 완료가 다른 날짜에 섞이지 않는다. 자정·시간대 변경·장기간 미접속 뒤에도 지난 빈 날짜에 가짜 완료/보상이 생성되지 않는다.
- [ ] 완료 수 0→1→2→4개에서 정수가 0→10→18→25로 증가하며 재전송/완료 취소로 중복 지급되지 않는다. 완료 취소 시 이미 받은 정수가 회수되지 않는 현재 규칙을 확인한다.
- [ ] 첫 입장·같은 날 재입장·수동 재열기·다음 날·계정 전환에서 팝업 확인 상태가 맞다. 새 획득을 보지 않고 닫힘 도중 갱신이 와도 보지 않은 획득을 확인 처리하지 않는다.
- [ ] 첫날 이름/건너뛰기/나중 변경, 활동일 1·4·7일 세 이야기, 21일+세 선택 뒤 성체, 계속 생활, 사용자가 시작한 배웅·다음 알·재회 편지를 완주한다.
- [ ] 집중/움직임/일상 세 경로와 A/B 선택에서 즉시 문장·남은 소품·다음 방문 결과가 다르다. 진로 근거 3개가 실제 누적 기록/선택에 맞다.
- [ ] 이야기 결과를 2초 이상 읽고 확인/닫기/배경으로 닫으면, 팝업이 내려간 뒤 정령이 한 번 기뻐한다. 닫기 연타에 보상·반응이 반복되지 않고, 동작 줄이기에서는 몸 이동 없이 표정이 바뀐다.
- [ ] 같은 날 독립→알 선택 후에도 실제 날짜가 유지된다. 이전 완료의 취소·재완료로 새 정령 활동일이나 정수가 복제되지 않는다. 정령 없이 다음 날 진입/완료/알 선택도 확인한다.
- [ ] 두 달·두 정령의 앨범, 원본 과거 정정, 기존 월 초상·사건 보존, 월 전환의 과거 조회 실패/재시도를 확인한다.

### 소비·저장·기기

### 재미와 표현 품질 — 사람의 플레이 평가 필요

기능 테스트 통과와 별도로 아래를 실제 플레이 후 답한다. 현재의 자동/프로그램 검증을 재미의 PASS로 환산하지 않는다.

- [ ] 설명을 읽기 전에도 정령이 독서/산책/만들기/차/휴식 중 무엇을 하는지 구별되는가?
- [ ] 버튼은 누르는 순간 반응하고 손을 떼면 안정되며, 정령의 몸·그림자·소품이 서로 떨어져 움직이는 느낌이 없는가?
- [ ] 오늘 실제로 한 일과 정령의 반응 사이 연결을 사용자가 자신의 말로 설명할 수 있는가?
- [ ] A/B 선택 후 무엇이 달라졌는지 소품·다음 대사·앨범에서 찾을 수 있는가?
- [ ] 1·4·7 활동일의 사건 뒤 다시 들어올 이유가 생기는가? 첫 주 이후 반복감이 커지는 시점도 기록한다.
- [ ] 정령의 성장 모습과 월별 기억에서 함께한 시간이 느껴지는가? 성체 이후 계속 동행하거나 배웅하고 싶은 이유가 있는가?
- [ ] 배경·캐릭터·새 성장 시트의 선/색/그림자가 함께 어울리는가? 새 시트 가장자리의 잔여 색상 픽셀, 소품의 바닥 접촉, 작은 글씨는 아트 검수에 별도 기록한다.
