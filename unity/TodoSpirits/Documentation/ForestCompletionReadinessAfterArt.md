# 아트가 준비된 뒤에도 남는 완성 조건

확인: 2026-09-18 · 근거: 현재 저장소 코드, [정령의 하루 상세 기획 v4](ForestDailyExperiencePlanV4.md), [서버 인수 문서](ForestServerDataApiHandoff.md), [기존 QA](Concept01ArtKitTestReport.md) · 이 문서는 아트 추가를 가정한 **잔여 작업 점검**이다. 변경 구현이나 새 플레이 테스트 결과가 아니다.

## 결론

**아트 리소스를 모두 받아도 게임은 완성되지 않는다.** 특히 실제 TODO 데이터가 Unity까지 오지 않고, 첫 입장 팝업과 일정에 따른 정령 반응이 동작하지 않는다. 새 아트는 P1의 시각 차이를 만들 재료이며, 연결·상태·대사·사건·저장·검증은 개발과 콘텐츠 작업으로 남는다.

## 아트 외부의 선행 결정과 검증

1. **서버·Android 계약:** 기존 `GET /api/task/calendar`를 그대로 활용할지 숲 스냅샷 API를 추가할지, 단조 증가 revision과 계정 시간대/자정, 제목·카테고리·51건 이상 입력을 정한다. 클라우드 숲 저장은 제품 결정 사항이며 로컬 MVP의 선행 필수 API로 단정하지 않는다.
2. **콘텐츠 제작:** 사용자 실제 기록을 임의로 바꾸지 않는 정령 일정 문장, 예정/완료/빈 기록/오류 대사, 기질·기분별 말투, 세 유형의 사건 대본·선택 결과를 작성·검수한다. 이 텍스트는 그림으로 대체되지 않는다.
   정령 목소리·효과음의 범위도 v4 §9에서 미결정이며, 오디오 제작을 포함할지는 제품 결정이 필요하다.
3. **품질 검증:** 기존 76/76 EditMode 통과와 APK 빌드/서명은 Art Kit·기존 로직의 기준선이다. v4의 첫 입장→정령 터치→선택→다음 방문→월별 기억 전 과정과 Android 실기기 연동은 통과 기록이 없다. [v4 QA 시나리오](ForestDailyExperiencePlanV4.md#81-qa-수락-시나리오) 및 기기에서 재검증해야 한다.
4. **배포 준비:** 기존 QA APK의 패키지 ID는 `com.DefaultCompany.TodoSpirits`였고 실기기 성능·GPU 메모리·터치/노치·재설치 후 저장 복원은 미검증이다. 아트 추가 뒤 Atlas와 용량/성능도 다시 측정한다.

## 실제 완료 판정

아트 파일 전달은 **납품 후보**로만 본다. P0~P3 각각의 기획서 완료 기준을 실제 Android 계정과 0·1·여러 TODO 및 2개월 샘플에서 통과하고, P4 정책을 정해 장기 저장/재접속까지 검증해야 목표 경험의 완료를 선언할 수 있다. 현재 가장 먼저 진행할 일은 아트 제작과 병행 가능한 **Android↔Unity 오늘 데이터 연결 및 P0 첫 입장 화면 구현**이다.
