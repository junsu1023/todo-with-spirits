# 정령의 하루 — 첫 입장과 생활 반응 상세 기획 v4

작성: 2026-09-18 · 문서 성격: **목표 경험과 구현 수락 기준** · 현재 앱의 구현 완료 보고가 아님

## 0. 이 문서의 결정 수준

| 표시 | 뜻 |
| --- | --- |
| **사용자 확정** | 이번 대화에서 사용자가 직접 설명한 흐름. 화면과 구현의 우선 기준. |
| **이번 기획안** | 그 흐름을 실제로 만들기 위해 구체화한 UX·콘텐츠·기술 정책. 플레이 검증 후 조정 가능. |
| **결정 필요** | 사용자가 확정하지 않았고 선행 문서 사이에도 차이가 있는 규칙. 승인된 규칙처럼 구현하지 않는다. |
| **현재 구현** | 2026-09-18 저장소에서 확인한 사실. 목표 경험과 구분한다. |

근거: 사용자의 첫 입장 팝업·정령 터치 요구, 선행 「생활 기록형 정령 육성 방향」 제안, [Prototype GDD v2](../../Docs/TODO_SPIRIT/TODO-SPIRIT%20ProtoType%20기획서.md), [Concept 01 Art Kit 적용 기록](Concept01ArtKitIntegration.md). 이전의 제작 타이머 중심 v3 초안과 컨셉 이미지의 레벨·보석·새싹 캐릭터는 이 문서의 확정 근거가 아니다.

첫 입장 팝업은 이전 Art Kit 문서의 `오늘 요약 기본 접힘`보다 **이번 사용자 요구를 우선**한다. 팝업은 읽기와 정령 반응을 위한 화면이며 TODO 추가·수정·완료 조작은 계속 호스트 TODO 앱이 맡는다.

## 1. 게임이 주는 핵심 경험

> 내가 오늘 해야 했던 일과 실제로 해낸 일이 정령의 하루 일정·행동·대사에 반영되고, 함께 고른 선택이 다음 장면과 월별 기억에 남는다.

하루의 재미는 다음 네 단계에서 발생한다.

1. **발견:** 첫 입장 팝업에서 내 일정/습관/TODO와 정령의 하루를 나란히 확인한다.
2. **반응:** 팝업을 내려 숲으로 들어가 정령을 터치하면 그날의 활동, 정령의 기분과 성격에 맞는 말을 듣는다.
3. **선택과 기대:** 특별한 사건에서 두 방식 중 하나를 고르면 다음 방문의 사건·소품·행동이 달라진다.
4. **기억:** 월별 앨범에서 실제로 한 일과 당시 정령의 모습·선택 결과를 함께 돌아본다.

TODO 앱의 일정 입력·수정·완료는 호스트 앱이 담당한다. 게임을 즐기기 위해 게임 안에서 별도 TODO를 만들거나 매일 모든 메뉴를 누를 필요는 없다. 정수는 기존 보상 규칙을 쓰며 EXP 바·보석·가챠·출석 페널티를 추가하지 않는다.

## 2. 하루 사용자 흐름

```text
TODO 앱에서 오늘의 일정·습관 확인/완료
  → 그날 처음 게임 입장
  → 오늘 데이터 확인 중(성공·오프라인·오류를 구분)
  → [내 오늘 + 정령의 하루 일정 + 획득 내용] 팝업 자동 표시
  → 카드 빈 영역 / 확인 버튼 / 배경 터치
  → 팝업이 아래로 내려가며 숲이 드러남
  → 숲 중앙의 정령 터치 → 오늘과 정령 성격에 맞는 대사
  → 사건이 있는 날에만 의미 있는 선택 → 변화 확인 또는 다음 방문 기대
  → 필요하면 오늘 기록·월별 앨범 확인 → TODO 앱으로 복귀
```

### 2.1 당일 첫 입장 판단 — 사용자 확정 + 이번 기획안

- **사용자 확정:** 그날 게임에 처음 들어왔을 때 팝업이 자동으로 나온다. 팝업을 닫으면 인게임 숲과 정령이 보인다.
- **이번 기획안:** 자동 노출 여부를 `accountId + 기준 날짜 + 표시 완료 상태`로 저장한다. 같은 날 재입장할 때는 자동 노출하지 않으며, 사용자가 숲에서 오늘 내용을 다시 열 수 있는 진입점은 유지한다. 계정이 바뀌면 다른 계정의 표시 상태와 저장을 사용하지 않는다.
- 오늘 데이터가 확인되기 전에는 빈 일정을 확정된 오늘로 보여주지 않는다. 로딩·통신 오류·정상적인 일정 0개를 다른 상태로 표시한다.
- 오프라인/오류에도 숲 진입은 가능하다. 이 경우 팝업에 마지막 확인 시각과 `최신 일정 확인 불가`를 표시하고 재시도를 제공한다. 확인되지 않은 TODO 완료나 보상을 추측하지 않는다. 이후 연결되면 플레이를 끊는 자동 팝업 대신 `오늘 기록이 갱신됐어요` 안내로 다시 열 수 있게 한다.
- 팝업을 본 뒤 같은 날 완료 항목이 바뀌면 목록·정령 예정/완료·정수 차액을 갱신한다. 이미 감상한 사건이나 선택을 무작위로 다시 뽑지 않는다.

## 3. 첫 입장 팝업 상세 명세

### 3.1 정보 구조 — 사용자 확정

팝업은 한 화면 안에서 아래 순서로 읽힌다. 작은 화면에서는 **본문만 스크롤**하고 날짜·닫기/확인 조작은 접근 가능하게 둔다.

| 영역 | 반드시 보일 정보 | 표현 규칙 |
| --- | --- | --- |
| 머리글 | 날짜, `오늘의 우리`, 최신 기록 확인 상태 | 사용자가 어느 날짜의 이야기인지 알 수 있어야 한다. |
| **내 오늘** | 오늘 해야 했던 일정·습관·TODO의 원래 제목과 완료/미완료 상태 | 원래 제목·카테고리·일정/습관 구분을 보존한다. 모두 완료했다고 꾸미거나 미완료를 실패로 묘사하지 않는다. |
| **정령의 하루** | 위 항목과 관련된 정령의 예정/이미 한 행동과 장소, 짧은 연결 이유 | `내 TODO → 정령이 준비한 일/해낸 일`이 눈에 보이게 연결된다. 여러 TODO를 한 장면으로 묶어도 원래 항목으로 돌아갈 수 있다. |
| **오늘 획득** | 새로 지급된 정수, 선택으로 생긴 소품·편지·발견물 등이 있으면 그 결과 | 실제로 저장된 획득만 표시한다. 정수 0이나 신규 획득 없음도 솔직하게 표시한다. 수령 버튼을 눌러야만 보상이 저장되는 구조로 만들지 않는다. |
| 닫기 | `숲에서 정령 만나기` 버튼, 카드의 조작 없는 영역, 팝업 바깥 배경 | 모두 같은 아래로 내려가는 닫힘 동작을 호출한다. |

### 3.2 `정령의 하루 일정`의 의미 — 이번 기획안

- 정령 일정은 사용자가 추가로 관리하는 할 일 목록이 아니다. **오늘 사용자 기록을 정령 세계의 생활 장면으로 번역한 순서표**다.
- 오늘 미완료인 항목은 정령의 `준비 중/기다리는 장면`, 완료된 항목은 `함께 한 장면`으로 구별한다. 미완료 TODO를 정령이 이미 했다고 적지 않는다.
- 서버가 실제 시작/마감 시각을 주지 않으면 `아침 9시` 같은 가짜 시각을 만들지 않고 `오늘의 계획 → 함께 한 일 → 쉬는 시간`처럼 순서만 표시한다. 실제 시각이 있다면 사용자 일정의 시각으로만 표시한다.
- 50개까지의 원본 TODO를 목록에서 확인할 수 있게 하고, 정령 장면은 대표 1개와 보조 최대 2개로 요약한다. 동일 카테고리의 작은 TODO 여러 개가 정령 성향을 과도하게 좌우하지 않게 **날짜별 카테고리 기여 상한**을 둔다. 정확한 점수표는 플레이 검증 항목이다.
- 카테고리 `미정`은 유효한 완료 기록이며 같은 정수·활동일을 받는다. 그 항목을 휴식이나 성실성으로 단정하지 않는다. 정령에게는 공통 생활/현재 진행 활동을 연결하고 실제 분야는 `미정`으로 남긴다.
- 오늘 일정 0개도 정상 데이터라면 정령의 자율적인 평범한 하루를 표시한다. 사용자가 하지 않은 일을 해냈다고 기록하지 않고 보상도 만들지 않는다.

### 3.3 보상 표시와 지급 시점 — 이번 기획안

현재 경제 규칙을 유지한다: 완료 0개=0, 1개=10, 2~3개=18, 4개 이상=25 정수(하루 누적). 같은 날 이미 받은 최고 보상보다 증가한 차액만 새로 지급한다. 팝업에는 `오늘 누적`과 `이번에 새로 획득`을 구분한다. 완료 취소·재완료·팝업 반복 열기로 추가 정수가 생기지 않는다. 선택 결과로 얻는 이야기 소품은 정수와 별개인 **기억용 결과물**이며 거래 재화로 늘리지 않는다.

보상/획득의 확정은 데이터를 검증하고 저장한 뒤에 이루어진다. 팝업 표시·닫힘 애니메이션·사용자의 터치는 지급을 재실행하지 않는다. 지급 실패 시 성공 연출을 보여주지 않고 재시도를 안내한다.

### 3.4 닫힘 동작 — 사용자 확정 + 이번 기획안

- **사용자 확정:** 팝업 자체, 확인 버튼, 바깥 배경을 터치해 닫을 수 있고, **아래로 내려가듯 사라지는 애니메이션** 뒤에 숲이 보인다.
- **이번 기획안:** 카드의 빈 영역/머리글 터치는 닫기, 목록 스크롤·항목 열기·재시도 버튼은 각 기능으로 처리해 읽는 중 우발적으로 닫히지 않게 한다. 배경 터치는 입력을 뒤의 숲 버튼에 전달하지 않는다.
- 닫힘은 카드 전체가 아래로 이동하면서 어두운 배경이 사라지는 약 0.25~0.35초 연출을 기준으로 검증한다. 연속 탭은 한 번만 처리한다. 종료 도중 앱이 백그라운드로 가거나 화면 방향이 바뀌어도 숲 입력 차단/표시 상태가 꼬이지 않는다.
- `동작 줄이기` 설정에서는 짧은 페이드 또는 즉시 전환을 제공한다. 애니메이션 완료 여부는 보상·성장·저장의 조건이 아니다.

## 4. 숲 메인과 정령 터치 반응

### 4.1 화면의 중심 — 사용자 확정 + 이번 기획안

- **사용자 확정:** 정령은 숲 메인의 중심에 계속 보인다. 팝업이 내려간 뒤 곧바로 정령과 교감할 수 있다.
- **이번 기획안:** 화면의 첫 시선은 정령의 현재 모습, 오늘 하는 일/준비한 일, 한 줄 대사로 간다. 사건이 있으면 `무슨 일이 있었어?`처럼 그 사건 하나를 주 행동으로 강조한다. 돌보기·선물·꾸미기·나들이는 주변의 보조 진입점으로 둔다.
- 숲이 게임의 기본 화면이며 하단 `오늘/숲/앨범` 내비게이션을 새로 만들지 않는다. 앨범은 숲 측면의 작은 아이콘으로 연다.
- 정령이 나들이 중이어도 메인에서 정령의 존재와 현재 상태를 이해할 수 있어야 한다. 정령을 통째로 없애는 연출은 사용자와 별도 합의 전에는 목표 화면으로 삼지 않는다.
- 성장 변화는 먼저 표정·자세·소품·사용 장소로 보여주고, 단계가 쌓일 때 외형 차이도 알아볼 수 있게 한다. 기존 **분홍 바람 정령**의 정체성을 유지한다. 컨셉 보드의 새싹 캐릭터로 교체하지 않는다.

### 4.2 터치 대사 선택 규칙 — 사용자 확정 + 이번 기획안

**사용자 확정:** 정령을 터치하면 그날의 일정/완료, 정령의 기분과 성격에 맞는 대사가 나온다.

| 우선 상황 | 대사 내용의 근거 | 예시 성격 |
| --- | --- | --- |
| 새 사건/획득/귀환이 있음 | 실제 저장된 사건과 결과 | 발견을 보여주거나 다음 선택을 알려준다. |
| 오늘 새 완료가 있음 | 해당 TODO의 원래 제목·카테고리와 정령 행동 연결 | `산책을 마쳤구나. 나도 숲길의 새 표식을 찾았어.` |
| 오늘 예정만 있고 완료는 없음 | 오늘 할 일의 존재와 정령의 준비 | `책을 읽기로 했구나. 나는 수첩을 펴 놓고 기다릴게.` |
| 기록 0개/동기화 불가 | 확인된 빈 목록 또는 연결 상태 | `오늘은 천천히 둘러볼게.` / `오늘 기록은 아직 확인하지 못했어.` |

- 같은 근거에서도 정령 기질에 따라 말투와 관심 행동이 달라진다. 호기심 많은 정령은 새 장소·발견을, 꼼꼼한 정령은 정리·기록을 언급할 수 있다. **기분은 정령의 게임 상태**(오늘 한 행동, 선물, 나들이, 사건)이며 사용자의 정신·건강 상태를 추측하지 않는다.
- 한 번 탭하면 짧은 표정/몸짓과 한 줄 대사가 나온다. 같은 날 연속 탭은 준비된 2~3개 문장을 순환하거나 잠깐 멈춘다. 재화를 주거나 반복 탭을 요구하지 않는다. 사건 팝업을 열기 위한 터치와 평상시 대사 터치를 구분한다.
- 근거 없는 카테고리·감정·시간 정보는 대사에 넣지 않는다. 지원되지 않는 조합에는 성격별 공통 대사를 쓰되 원래 TODO 제목/완료 상태를 바꾸지 않는다.

**이번 기획안의 대사 데이터 구성:** `확인된 오늘 상태(예정/완료/사건) × 정령의 기분 태그 × 선천 기질`에서 문장 후보를 고른다. 기분 태그의 첫 검증 범위는 `기대`, `기쁨`, `차분함` 세 가지다. 이는 정령의 반응 상태이지 사용자의 감정 진단이 아니다. 같은 사실을 말하더라도 호기심 많은 정령은 `다음에는 어디를 볼까?`, 꼼꼼한 정령은 `발견한 것을 수첩에 적었어`처럼 표현한다. 첫 검증은 대비가 보이는 기질 조합 2개와 각 상태별 최소 2문장을 준비하고, 8종 전체 조합 확장은 별도 콘텐츠 작업으로 다룬다. 문장은 검수된 고정 콘텐츠로 시작하며 생성형 AI 자유 대화는 범위에 넣지 않는다.

## 5. 재미의 본체: 선택 → 눈에 보이는 변화 → 다음 방문

### 5.1 최소 사건 구조 — 이번 기획안

첫 검증 범위에서 **집중 활동 중심 / 움직임 중심 / 혼합 또는 미정 중심**의 세 입력 유형을 준비한다. 유형마다 `발견 → 시도 → 작은 완성`의 세 장면을 만든다. 최초 유효 완료일에 첫 장면, 이후 활동일과 실제 기록을 바탕으로 다음 장면이 열린다. 현재 코드의 1·4·7 활동일은 시험용 트리거로 활용할 수 있으나 최종 밸런스 값으로 확정하지 않는다. 쉬었다고 사건이 실패하거나 정령이 퇴보하지 않는다.

각 사건은 아래 세 가지 중 **모두**에 차이를 남겨야 선택의 의미가 보인다.

1. 즉시: 다른 정령 반응과 후속 사건 문장.
2. 화면: 선택에 맞는 소품 또는 장소의 변화.
3. 다음 방문: 선택을 기억한 행동/대사나 사건 결과.

사건 결과는 앱을 닫고 다시 들어와도 동일하다. 선택은 실제 TODO 카테고리나 완료 사실을 수정하지 않는다. 성체 특기를 사용한다면 여러 날의 실제 기록을 근거로 후보를 설명하고, 선택은 **표현·전문성의 방향**을 정하게 한다. 어느 결과도 우등/열등 등급이 아니다.

### 5.2 실제 카테고리 → 재사용 장면의 초기 매핑 — 이번 기획안

모든 카테고리에 별도 맵을 만드는 대신 책상·공작대·숲길·티테이블·쉼터의 다섯 장소와 소품을 조합한다. 아래는 **장면 후보**이며 단일 TODO로 정령의 성격/진로를 확정하는 규칙이 아니다.

| TODO 카테고리 | 정령의 생활 후보 | 눈에 보일 최소 단서 |
| --- | --- | --- |
| `WORK_STUDY` | 책상에서 읽고 정리하기 | 펼친 책·메모 |
| `HEALTH` | 숲길을 걷고 몸 풀기 | 산책 가방·길 표식 |
| `LIFE` | 공작대와 집 주변을 정돈하기 | 손질한 생활 소품 |
| `RELATIONSHIP` | 티테이블에서 인사·대화 준비하기 | 찻잔·편지 |
| `GROWTH` | 책상/공작대에서 새 기술 연습하기 | 연습 노트·도구 |
| `HOBBY` | 공작대에서 즐거운 표현 활동 | 작은 그림·만든 물건 |
| `REST` | 쉼터에서 쉬고 주변을 관찰하기 | 방석·잔잔한 표정 |
| `FINANCE` | 책상에서 필요한 물건을 계획하기 | 장부·정리한 보관함 |
| `NONE`(`미정`) | 기존 진행 활동 또는 공통 교감 | 사용자 분야를 추측하지 않는 정령의 자율 장면 |

정령의 기질은 같은 장소 안의 움직임·소품 선택·말투를 바꾼다. 완료하지 않은 항목의 장면은 `예정`으로만 표시한다. 카테고리와 실제 행동의 연결 이유를 오늘 팝업과 날짜별 기록에서 읽을 수 있어야 한다.

### 5.3 경험 예시 — 콘텐츠 예시이며 사용자 기록 아님

| 단계 | 실제 입력 예시 | 정령 장면 | 사용자의 선택 | 이후 확인할 차이 |
| --- | --- | --- | --- | --- |
| 발견 | `책 읽기` 완료 + `가벼운 산책` 완료 | 책에서 본 잎과 숲에서 찾은 잎을 비교 | `수첩에 그리기` / `나무를 찾아가기` | 수첩 또는 작은 탐험 가방이 숲에 나타남 |
| 시도 | 다음 활동일의 실제 기록 | 앞선 선택의 소품을 사용 | `이웃과 나누기` / `우리만의 표식 만들기` | 다음 대사·사건의 상대/소품이 달라짐 |
| 작은 완성 | 이후에도 기록된 생활 | 정령이 경험을 정리해 작은 결말을 만듦 | 기억할 장면 선택 | 앨범의 당시 정령 초상·사건·선택 근거로 남음 |

이 예시는 산책이나 독서를 강요하는 콘텐츠 잠금 조건이 아니다. 건강·생활·관계·취미·휴식·자산·`미정` 등 다른 생활 유형에도 완주 가능한 공통 경로를 둔다. TODO 하나를 여러 개로 쪼갰다고 더 빠르게 좋은 진로를 얻지 않도록 한다.

### 5.4 하루 전체 예시 — 화면과 상태 전환 확인용

예시 입력은 `책 읽기`(완료, 성장)와 `가벼운 산책`(미완료, 건강) 두 개다. 실제 사용자의 행동을 가정하는 예시일 뿐이다.

1. **첫 입장 팝업:** `내 오늘 1/2`에 원래 두 제목과 상태를 표시한다. `정령의 하루`에는 `책을 읽고 잎을 수첩에 남김 · 함께 한 일`, `숲길을 걸을 준비 · 예정`을 구분한다. 실제 지급이 성공했다면 `오늘 누적 10 정수 / 이번에 새로 10`을 보여준다.
2. **팝업 닫기:** 카드의 빈 곳·확인 버튼·바깥 배경 어느 쪽이든 한 번의 하향 이동으로 닫힌다. 숲에는 정령과 수첩 소품이 보인다.
3. **정령 터치:** 정령은 완료한 독서 사실을 말한다. 호기심 많은 정령은 새 잎을 더 찾아보자고, 꼼꼼한 정령은 수첩에 정리했다고 반응한다. 미완료 산책을 `같이 걸었다`고 말하지 않는다.
4. **같은 날 산책 완료:** 호스트에서 갱신된 전체 목록을 받는다. 누적 18 정수 중 추가 차액 8만 지급한다. 새 전체 화면을 강제로 띄우지 않고 `오늘 기록이 달라졌어요` 안내로 다시 열 수 있다. 정령 대사에는 실제로 완료한 산책이 추가된다.
5. **다음 방문:** 사건 선택을 했다면 선택한 수첩/가방과 후속 장면을 보여준다. 월별 기록에는 두 원래 TODO와 당시 사건을 연결해 보관한다.

### 5.5 보조 요소의 역할

선물·꾸미기·나들이는 정령의 반응과 이미 진행 중인 이야기를 풍성하게 한다. 정수 소모 메뉴 세 개가 하루 플레이의 주 목적이 되지 않는다. 선물은 특정 반응/행동 표현에, 장식은 실제로 보이는 장소에, 나들이는 돌아온 뒤 확인할 사건/기억에 연결한다. 돈을 쓰지 않아도 첫 장면부터 작은 완성까지 경험할 수 있다.

## 6. 월별 기록과 재방문 동기 — 이번 기획안

- 한 달의 실제 완료 TODO·활동한 날짜·원래 카테고리를 확인한다. 여러 TODO를 완료한 하루를 여러 활동일로 세지 않는다. 실제 사용 시간이 없으면 `가장 오래 공부했다` 같은 추측을 하지 않는다.
- 같은 정령과 여러 달 함께해도 **월별 당시 초상**(그때 외형 단계·보이던 소품·관심사·선택 장면)을 따로 보존한다. 같은 달 정령이 둘이면 각각의 기간을 보여준다.
- 날짜를 열면 `내가 완료한 일 → 정령이 한 행동/사건 → 그날의 획득`을 연결해서 볼 수 있다. 이미 본 장면은 실제 기록 정정 뒤에도 당시의 이야기로 남기고, 월간 사실 요약은 정정된 데이터를 반영한다. 두 층의 기준 시각·버전을 표시한다.
- 첫 주에는 `다음에 어떤 일이 생길까`를 검증하고, 최소 한 달 후에는 `그때 내 생활을 기억하게 해 주는가`를 별도로 검증한다.

## 7. 데이터 책임과 현재 구현과의 차이

### 7.1 최소 입력 계약 — 이번 기획안

| 필드 | 용도 | 현재 확인 상태 |
| --- | --- | --- |
| `accountId`, 기준 `date`, 시간대, 순서 `revision` | 하루 최초 입장·계정 분리·오래된 응답 방지 | Unity 브리지는 `accountId/date/revision` 수신. 시간대 정책과 안정된 서버 revision은 협의 필요. |
| 오늘 전체 occurrence의 `id/title/category/isHabit/isCompleted` | 해야 했던 일·한 일의 팝업과 정령 일정 생성 | Unity `ForestTodoBridge`와 Android `ForestUnityActivity` 발신 코드에 연결. 실제 호스트 빌드/계정 실행 결과는 별도 검증. |
| 원래 일정 시각·완료 시각(있을 때) | 실제 시각 표시, 변경 안내 | 현재 Unity 스냅샷에는 없음. 없으면 시각을 꾸며내지 않는다. |
| 일별 보상 상태와 정령 사건/대사/획득 결과 | 중복 지급 방지, 같은 날 재진입, 월별 기억 | 현재 Unity 로컬 저장을 사용. 기기 간 이어하기를 원하면 서버 소유 정책 필요. |

기존 서버 `GET /api/task/calendar`는 오늘 전체 occurrence의 원천으로 활용할 수 있으나 Unity 수신 형식과 직접 같지 않다. [서버 인수 문서](ForestServerDataApiHandoff.md)에서 기존 API와 추가 계약을 구분한다.

### 7.2 구현 착수 시점의 차이 — 과거 기준선

| 목표 | 2026-09-18 이번 구현 착수 전 코드/QA에서 확인한 상태 |
| --- | --- |
| 첫 입장 자동 팝업, 아래로 내려가는 닫힘 | 현재 `TodaySummary`는 숲에서 여는 읽기 전용 시트다. 첫 입장 자동 노출/하향 닫힘은 확인되지 않았다. |
| 해야 했던 일 + 한 일 + 정령의 하루 일정 + 획득 동시 표시 | 오늘 시트에는 TODO 제목·카테고리·완료 여부만 표시된다. 정령 일정/보상 결합 화면은 없다. |
| 실제 TODO와 연결된 터치 대사 | 현재 정령 터치는 고정 인사 대사이며 Android→Unity TODO 발신부는 없다. |
| 행동/장소/기질에 따른 눈에 보이는 생활 차이 | 현재 숲은 한 배경과 기존 4포즈의 작은 움직임 중심이다. 다섯 장소의 생활 장면은 없다. |
| 선택 후 후속 사건·소품·행동 차이 | 고정 잎 이야기의 선택 문구와 일부 소품/편지는 있으나 입력 유형별 사건과 후속 행동 차이는 구현되지 않았다. |
| 월별 당시 정령 초상 | 월별 TODO·선택·달력은 있으나 당시 외형/소품의 스냅샷은 없다. |

이 표는 품질 문제를 확인했던 **착수 전 기준선**으로 보존한다. 이후 첫 입장 팝업·생활·터치 반응·분기 사건·월별 기억·성장 외형·Android 발신 코드를 구현했다. 현재 기능은 [개발자 안내](ForestFeatureAndDeveloperChecklist.md), 직접 실행한 검증과 남은 항목은 [수락 기록](ForestPrototypeAcceptance.md)을 따른다. 구현 존재를 실기기/최종 품질 통과로 간주하지 않는다.

## 8. 구현 순서와 완료 기준 — 이번 기획안

| 순서 | 만들 결과 | 완료 판정 |
| --- | --- | --- |
| P0 데이터·진입 | Android의 오늘 전체 TODO → Unity, 첫 입장 팝업, 정수/획득 표시, 하향 닫힘 | 실제 계정의 0/1/여러 항목에서 `내 오늘 → 정령의 하루 → 숲`이 이어지고 재입장·오프라인·중복 보상이 안전함 |
| P1 정령 반응 | 행동/장소/기질별 최소 3종 생활 장면과 터치 대사 | 같은 TODO 입력도 서로 다른 기질에서 대사·몸짓 차이를 볼 수 있고, 대사가 실제 완료 상태와 모순되지 않음 |
| P2 이어지는 사건 | 3개 입력 유형의 세 장면 사건, 각 선택의 즉시/시각/후속 차이 | 선택 A/B를 비교하면 다음 방문의 소품·대사·사건 중 명확한 차이가 있음 |
| P3 월별 기억 | 당시 초상과 TODO→정령 행동 연결, 과거 정정 정책 | 두 달의 가상 샘플을 보고 그달의 실제 활동과 정령 변화를 설명할 수 있음 |

### 8.1 QA 수락 시나리오

## 9. 제품 결정과 남은 조정 항목

1. **이름과 장기 성장 — 사용자 위임에 따른 이번 프로토타입 결정:** 첫날 이름을 제안하되 건너뛰기와 나중 변경을 허용한다. 첫 주에는 1·4·7 활동일에 작은 사건을 보여주며, 성체 기준은 21 활동일과 이야기 선택 3회 모두 충족으로 한다. 주 4~5일 기록하는 경우 약 4~6주가 되는 초기 균형값이며 플레이 후 조정할 수 있다. 성체 이후에도 같은 정령과 계속 생활할 수 있다. 사용자가 원할 때 새 동행/배웅을 시작하며, 정식 이름 확인 → 마지막 동행 → 배웅 → 알 3개 선택 → 다음 정령으로 이어진다. 과거 기록은 유지한다. 이 결정은 선행 v2의 성체 이후 첫 이름과 기존 코드의 14일 시험 규칙을 대체하는 **목표 정책**이며 구현·완주 검증 완료를 뜻하지 않는다.
2. **정령의 기분 표현:** 고정 태그 수·문장 어투·기질 조합에 따른 대사량과 목소리/효과음 범위를 콘텐츠 제작 전에 정한다. 사용자 기분 추정 기능은 범위에 넣지 않는다.
3. **성장 사건의 판정표:** 실제 활동 경향, 카테고리별 날짜 기여, 기질, 선택의 가중치와 늦은 동기화 후 재판정 시점을 검증한다. 숫자 자체보다 사용자가 결과의 근거를 이해하는지 먼저 테스트한다.
4. **기기 간 저장:** 현재 숲 기록·정수·팝업 확인 상태는 Unity 로컬이다. 계정 간/기기 간 이어하기를 제공할지와 서버가 경제의 최종 권한을 가질지 결정한다.

### 9.1 장기 성장 방식을 이렇게 정한 이유

사용자는 두 가지 성장안 중 추천안을 선택해 작업하고 기획에도 반영하도록 위임했다. 이번 프로토타입은 **기록한 날의 축적과 정령과의 관계**를 중심에 둔다.

- **첫날 이름:** 정령을 처음 만났을 때부터 나의 동행으로 느끼게 한다. 이름을 고르는 일 때문에 숲 진입이 막히지 않도록 건너뛰기와 이후 변경을 제공한다.
- **1·4·7 활동일의 사건:** 장기 성장 전에 첫 주에도 선택의 결과와 다음 방문의 이유를 경험하게 한다. 달력상 며칠이 지났다는 이유만으로 사건을 소진하지 않는다.
- **21 활동일과 세 선택 후 성체:** 하루에 많은 TODO를 끝내는 것보다 여러 날 함께한 기록에 무게를 둔다. 같은 날 완료 수를 늘려 활동일을 여러 번 얻을 수 없다. 세 사건을 함께 선택한 뒤 성체가 되므로 활동일만 늘려 이야기를 건너뛰지 않는다. 기록하지 않은 날에는 활동일을 깎거나 관계를 벌주지 않는다.
- **성체 이후 계속 생활:** 성장이 끝나도 오늘의 일정, 생활 장면, 대화, 나들이와 앨범을 이어간다. 성체 도달은 강제 이별의 시점이 아니다.
- **선택하는 배웅:** 설정의 다음 동행 안내에서 사용자가 시작한다. 확인 → 이름 확인 → 마지막 동행 → 배웅 → 알 세 개 중 선택 순서로 진행하며, 이전 정령의 기록은 앨범에 남긴다.

21일은 첫 프로토타입의 조정 가능한 기준이다. 플레이 검증에서는 숫자 달성보다 `처음 일주일 안에 변화를 느끼는가`, `성체 이후에도 같은 정령과 머물 이유가 있는가`, `다음 정령으로 넘어가도 기록이 이어지는가`를 확인한다.

### 9.2 배웅 당일의 기록과 다음 정령

- 알을 고른 날에도 실제 날짜를 유지한다. 새 정령을 만났다는 이유로 게임 날짜를 내일로 넘기지 않는다.
- 완료가 처음 확인된 `날짜 + TODO occurrence`의 성장 귀속을 보관한다. 이전 정령과 완료한 항목은 취소·재완료해도 새 정령의 성장으로 복제되지 않는다.
- 오늘의 원본 목록에는 모든 항목을 계속 보여주고 `이전 정령과 한 일`을 구분한다. 새 정령은 자신에게 귀속된 완료로 생활과 성장을 이어간다.
- 배웅 후 알을 고르기 전에도 최신 TODO 사실과 실제 날짜를 받을 수 있다. 이때 새로 완료한 항목의 정수는 저장하고, 아직 없는 새 정령의 활동을 꾸미지 않는다. 알 선택 시 대기 중인 해당 날짜의 완료를 새 동행에 연결한다.
- 정수는 계정의 날짜별 최고 지급액으로 계산한다. 정령을 교체해도 하루 25 정수 상한과 이미 확인한 획득 표시가 초기화되지 않는다.

### 9.3 단계별 모습과 기질별 몸짓

- 외형은 어린 무장식 모습 → 관심 단계부터 잎 스카프·외꼬리 → 성체의 잎 망토·쌍꼬리로 구별한다. 기존 어린 정령과 P1 독서 후보는 유지하며 중간·성체는 별도 표정 시트를 사용한다.
- 메인, 이름/배웅 팝업, 재방문 편지는 해당 정령의 단계로 표시한다. 앨범은 저장된 당시 단계로 표시하며 현재 정령이 자랐다는 이유로 과거 초상을 성장시키지 않는다.
- 관찰 기질은 작은 고개 기울임과 느긋한 템포, 활동 기질은 가벼운 인사와 조금 빠른 템포로 표현한다. 단순한 연속 확대·축소보다 준비→한 번의 행동→가라앉는 흐름을 쓴다.
- 동작 줄이기를 켜면 몸과 소품의 이동·회전·확대는 멈추고 표정과 대사로 반응한다. 누락된 독서 두 번째 프레임이나 P1의 나머지 8종이 완성됐다는 뜻은 아니다.

### 9.4 선물 이후의 생활과 나들이 기억

- 선물 6종은 하루 1회, 15 정수다. 기질별 즉시 반응에 더해, 다음 날부터 3일 동안 현재 정령에게 준 최근 유효 선물의 활동을 메인에서 우선 보여준다. 나들이 중에는 나들이 표현을 우선한다.
- 선물 생활은 독서/휴식/만들기·돌보기/차/탐색으로 구별한다. 오늘의 실제 TODO 활동은 요약에 함께 남기고 선물 생활에는 출처·날짜를 표시한다. 선물만으로 완료 수, 성장 활동일 또는 보상을 늘리지 않는다.
- 대표 생활에 선물을 우선 표시하는 것은 결과를 알아보기 쉽게 하기 위한 프로토타입 정책이다. 무작위 후보로만 처리하던 초안 대신 적용하며, 3일 반복의 적절성은 사용자 플레이 평가로 조정한다. 유효 기간이 끝나거나 새 정령을 만나도 과거에 감상한 선물 생활은 당시 앨범에 보존한다.
- 40 정수·4시간 나들이는 준비물 3종 중 하나를 고른다. 진행 중 대사와 귀환 대사를 구별하고, 귀환 날짜 앨범에서 당시 모습·준비물·사건·발견물을 다시 읽는다. 다시 읽기와 날짜 기록으로 돌아가기는 추가 지출·획득을 발생시키지 않는다.
- 실제 실행 근거는 `Validation/ForestPrototype/intervention-*.json`과 `intervention-ui-qa.md`를 따르며, 이 정책 문서만으로 검증 완료를 판정하지 않는다.
