# 숲 앱 출시 UI 개편 기록

> 최신 개편은 [ForestReleaseUiV3.md](ForestReleaseUiV3.md)를 참고한다. 아래는 이전 개편 기록이며, 현재 화면은 `Validation/ReleaseUiV3`에 있다.

작성일: 2026-09-17 · 대상: Unity 클라이언트 · Unity 6000.3.16f1

이 문서는 `Presentation/Forest`의 실제 코드와 에셋 임포트 코드를 확인한 구현 기록이다. UI 개편 결과와 출시 전에 남은 검증을 구분한다. 실제 실행에서 확인한 결과는 아래 검증 표에 기록한다.

저장소 지침의 공용 위키 진입점 `../../Wiki/01 LLM Context.md`는 현재 체크아웃에서 발견하지 못했다. 이 문서는 Unity 프로젝트의 `Documentation`에 두며, 기존 `unity/Docs`의 로컬 전용 기획서 규칙을 변경하지 않는다.

## 개편 방향과 실제 화면

TODO는 일정 관리가 먼저 읽히고, 숲은 정령과의 관계가 먼저 보이며, 앨범은 생활 기록을 다시 꺼내 보는 공간으로 나누었다. 동일한 흰 카드와 텍스트 버튼을 반복하던 구조에서 화면마다 역할이 드러나도록 바꾸었다.

| 화면 | 구현된 구성 | 목적 |
| --- | --- | --- |
| 공통 | 아이보리 바탕, 짙은 숲색 텍스트, 세이지 선택 상태, 분홍 강조, 직접 그린 아이콘, 고정 헤더·하단 탐색 | 정보 위계와 일관된 인상 |
| 오늘 | 주간 날짜 띠와 기록 표시, 작은 정령 반응, 완료 진행 막대, 미완료 목록·접는 완료 목록, 제목·카테고리·반복 표시 | 할 일을 빠르게 읽고 완료·수정 |
| 숲 | 화면 폭을 사용하는 숲 원화, 정령 애니메이션, 활동일·정수, 선택 이야기, 돌보기·꾸미기·나들이 | 정령과 선택 결과를 중심에 배치 |
| 앨범 | 월 이동, 가로 정령 선택, 숲 폴라로이드, 실제 기록 수·카테고리 막대, 선택 타임라인, 독립·재회 편지 | 생활과 선택이 남긴 결과를 다시 확인 |
| 바텀시트 | 고정 제목·닫기, 스크롤 본문, 입력 오류 안내, 키보드 높이 대응 | 화면을 과도하게 축소하지 않고 입력·긴 글 제공 |

오늘의 주간 날짜 띠는 현재 주의 상태 표시다. 과거 날짜를 선택해 일정을 수정하는 달력 기능은 아니다.

숲 배경 위에는 텍스트를 읽기 위한 그라데이션을 두며, 꾸미기 소품은 별도의 투명 배경 Sprite로 표시한다. 정령은 기존 네 가지 표정 Sprite와 절차적 움직임을 유지한다. 별도 성체 원화를 새로 완성한 것은 아니다.

## 상호작용과 데이터 의미

- 할 일 추가뿐 아니라 제목·카테고리·매일 습관 여부를 수정할 수 있다. 수정은 현재 날짜 기록을 다시 계산하며, 과거 일별 기록의 제목·분류·루틴 스냅샷을 소급 변경하지 않는다.
- 완료 취소와 다시 완료에서 정수를 중복으로 얻지 않도록 기존 일일 최대 지급 규칙을 사용한다.
- 네이티브 TODO 연결 상태에서는 Unity가 로컬 목록을 수정하지 않는다. 수정하려고 하면 연결된 앱에서 변경하라는 안내를 보여 준다.
- 선물, 꾸미기, 나들이는 기존 서비스 규칙을 사용한다. 정수 부족·오늘 이미 선물함·나들이 중 등의 상태를 표시하며 가능한 행동만 활성화한다.
- 알과 나들이 준비물은 먼저 선택하고 별도 버튼으로 확정한다. 편지는 열기만으로 바로 지급하지 않고 명시적인 수령 버튼을 거쳐 저장한다.
- 동작 줄이기는 정령의 위치·회전·크기 움직임과 UI 버튼의 눌림 확대·축소를 제한한다. 표정 교체와 텍스트 상태 변경까지 정지하는 옵션은 아니다.
- 탭을 다시 그릴 때 탭별 스크롤 위치를 보존하고 콘텐츠 크기에 맞춰 범위를 제한한다.
- 주요 화면과 앨범 버튼은 480 기준 UI 좌표에서 약 60 이상의 터치 높이를 사용한다. 실제 기기에서의 터치 편의성은 별도 확인이 필요하다.

## 앨범 기록 원칙

앨범은 해당 정령의 저장된 `DailyCompanionRecord`에서 선택 월의 완료 내역을 집계한다. 카테고리 막대는 완료 건수의 비중이며, 시간이 얼마나 투입되었는지나 사용자의 능력을 의미하지 않는다. 기록한 날은 완료가 한 건 이상 있는 서로 다른 날짜 수다.

`미정`은 중립색으로 표시한다. 제목에서 휴식·건강 등의 의미를 추론해 다른 생활 유형으로 바꾸지 않는다. 선택과 특기는 해당 선택 날짜가 월말보다 앞선 경우만 표시하며, 재회 편지도 수령한 월에서 읽을 수 있다.

정령의 이름을 붙인 날짜는 현재 저장 모델에 별도 필드가 없다. 따라서 과거 월에 미래의 이름을 노출하지 않기 위해, 독립일 이전의 앨범에는 보수적으로 `작은 정령`을 사용한다. 실제 이름의 역사까지 보존하려면 이름 부여 날짜 또는 이름 변경 이력이 필요하다.

만나기 이전 달에는 첫 만남 날짜와 해당 월로 이동하는 버튼을 제공한다. 기록이 없는 달은 빈 상태를 보여 준다. 아직 오지 않은 월로는 이동하지 않는다.

긴 정령 이름·선택 설명·편지는 텍스트의 `preferredHeight`로 높이를 계산한다. 한국어 폰트의 실제 줄 높이 때문에 고정 높이에서 문자가 사라지는 문제를 피하도록 통계 숫자·섹션 제목·작은 레이블의 높이도 별도로 확보했다.

## Editor 재검증 순서

1. 작업 씬의 미저장 변경을 먼저 확인한다. 설치가 필요하면 Play를 종료한 뒤 `TodoSpirits > Install Forest UI`를 실행한다. 설치 코드는 프리팹과 씬 배선을 다시 만들므로 이미 편집 중인 씬을 무심코 덮어쓰지 않는다.
2. `00_Boot`에서 시작한다. 날짜 가속·수령 검증은 전용 QA 저장으로 실행한다. 부트스트랩의 Editor 전용 `TodoSpirits.ForestVerificationSave` 지정 기능을 사용할 수 있으며 실제 사용자 저장을 초기화하지 않는다.
3. `ForestEditorPreview.SetSize(540, 1000)`과 `SetSize(360, 640)` 또는 같은 크기의 Game View를 사용한다. 오늘·숲·앨범의 헤더, 내비게이션, 내용 끝까지 스크롤을 확인한다. 숫자·한국어 제목·2줄 설명이 빈칸이거나 잘리지 않아야 한다.
4. 긴 한국어 제목의 일정과 습관을 추가한다. 빈 입력 오류 후 입력값이 유지되는지, 카테고리·반복 상태가 즉시 보이는지, 완료와 취소가 반응하는지 확인한다. 행을 눌러 제목·카테고리·반복을 수정한다.
5. 전날 완료가 있는 습관을 오늘 수정하고 앨범의 전날·이전 월 기록이 바뀌지 않는지 확인한다. `미정` 기록만 있는 날이 휴식 등의 유형으로 해석되지 않는지도 확인한다.
6. 모든 시트에서 본문을 스크롤한 뒤에도 닫기 버튼이 고정되어 있는지 확인한다. 긴 이름과 긴 편지에서는 본문 전체에 접근할 수 있어야 한다. 동작 줄이기를 켜고 정령과 버튼 반응을 확인한다.
7. 돌보기와 선물을 확인하고, 정수가 부족한 구매·나들이가 실행되지 않는지 확인한다. 소품을 구매·장착·해제하고 다시 켠 후 상태를 확인한다.
8. 전용 QA 저장에서 `설정 > 개발 도구 > 검증용 · 다음 날로 이동`을 사용해 성장·선택·독립·다음 알·첫 재회 경로를 진행한다. 미수령 나들이가 있을 때 돌아온 이야기에 접근할 수 있는지도 확인한다.
9. 재회 수령 후 다시 켜서 중복 지급되지 않는지 확인하고, 앨범에서 해당 월의 편지를 다시 읽는다. 첫 만남 전 달과 특기 선택 전 달에 미래 정보가 표시되지 않아야 한다.
10. Unity Test Runner의 관련 EditMode 테스트를 실행한다. 비개발 Android 검증 APK는 `TodoSpirits > Build Forest Android Release APK`로 재생성한다. Development 메뉴도 유지하며, 개발 도구는 Editor와 Development 빌드에서만 표시한다.

## 출시 전 남은 위험과 범위

- 실제 Android 기기의 터치·소프트 키보드·시스템 뒤로 가기·안전 영역·접근성 글자 크기·TalkBack 동작은 Editor의 Game View만으로 검증할 수 없다. 현재 UI가 네이티브 접근성 트리를 제공한다고 단정하지 않는다.
- UI를 갱신할 때 화면 오브젝트를 다시 구성한다. 저사양 기기의 프레임 시간·GC·메모리·발열과 원화 압축 품질은 프로파일링이 필요하다.
- Android TODO 앱의 Unity as a Library 임베딩, 발신부, 수신 결과 콜백 및 계정 전환·클라우드 저장·과거 날짜 병합은 별도 통합 범위다. Unity 수신부가 존재하는 것과 네이티브 제품 통합이 완료된 것은 다르다.
- 기록은 현재 기기 저장에 의존한다. 앱 삭제·기기 교체 뒤 복구하는 계정 동기화 기능이 UI 개편으로 추가된 것은 아니다.
- 성체는 현재 특기·크기·소품·서사로 구분한다. 특기별 전용 성체 원화·전용 동작·리깅 제작은 남아 있다.
- 재회는 저장된 첫 재회와 편지 다시 읽기 흐름이다. 장기 반복 재회 사건, 지속적인 월별 콘텐츠 공급, 재방문 알림·푸시 스케줄은 이번 UI에 구현되었다고 볼 수 없다.
- 성장 기간·정수 가격·첫 재회 시점은 기존 테스트용 튜닝을 사용한다. 출시 전 사용자 테스트로 3~5분 이용 흐름과 장기 재미를 별도 검증해야 한다.
- Google Play 제출용 서명·릴리스 번들·스토어 등록과 배포는 이 UI 개편의 완료 판정에 포함하지 않는다. 개발용 APK 빌드 결과는 스토어 출시 검증을 대신하지 않는다.

## 추가로 수정한 진행 문제

- 성체 상태에서도 진행 중인 나들이의 결과에 접근하도록 귀환 버튼을 유지한다. 미수령 여행 때문에 독립이 막히는 UI 경로를 수정했다.
- 이름 짓기를 키보드 대응 시트로 이동했다. 입력 중 자정 동기화는 보류하고, 저장 직전에 날짜를 맞춰 열린 초안을 지우지 않는다.
- 커스텀 아이콘에 CanvasRenderer 필수 선언을 추가했다. 최초 실행에서 확인한 누락 오류를 해결한 뒤 새 인스턴스로 검증했다.
- 배경/소품의 정확한 생성 프롬프트와 원본 유지 여부는 [ForestArtProvenance.md](ForestArtProvenance.md)에 기록한다.

## Android 검증 아티팩트

- 파일: Builds/Forest/TodoSpirits-Forest-release.apk. 이전 Development APK는 이번 UI 검증 결과로 사용하지 않는다.
- 실제 패키지 검사: arm64-v8a, minSdk25, targetSdk36, application-debuggable 표시 없음.
- 기존 프로젝트 식별자 com.DefaultCompany.TodoSpirits 및 기본 버전 설정은 변경하지 않았다. TODO 앱 내부 배포와 Play 제출용 패키지·서명·버전은 네이티브 통합 단계에서 맞춰야 한다.
- BuildReport totalSize는 빌드 관련 전체 크기이므로 APK 크기로 제시하지 않는다. 파일 자체의 크기와 SHA-256은 Validation/forest-release-apk.json, 빌드 결과는 Validation/forest-android-release-build.json에 보존했다.

최종 재시작에서 정령 2명, 12자 이름, 재회 수령, 장식 2개, 동작 줄이기 설정 복구를 확인했다. 별도 QA 경로는 현재 실행에만 쓰고 Editor SessionState override를 해제했으므로 다음 새 Play는 기본 저장을 사용한다.
