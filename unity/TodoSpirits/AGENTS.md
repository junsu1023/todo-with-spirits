한국어로 답변한다.

코드 작업 시 먼저 현재 저장소의 AGENTS.md와 관련 파일을 확인한다.
확인하지 않은 씬, 프리팹, 인스펙터 배선, 패키지 API, 클래스 존재 여부를 단정하지 않는다.
큰 구조 변경보다 작은 국소 수정, 명시적 DI 등록, Unity 직렬화 참조 안전을 우선한다.
코드를 변경한 경우 변경 파일, 변경 이유, 리스크, Unity Editor 검증 방법, 로컬에서 확인하지 못한 항목을 요약한다.

ITS 저장소에서는 AGENTS.md를 최우선 프로젝트 지침으로 따른다.

커밋 메시지는 Unity 프로젝트 변경의 경우 scope에 `(unity)`를 붙인다.
예: `chore(unity): create unity project`

## Project Wiki

작업 시작 시 `../../Wiki/01 LLM Context.md`를 저장소 공용 위키 진입점으로 읽고, 작업 영역과 관련된 노트를 확인한다.
위키의 설명과 실제 프로젝트 파일이 충돌하면 프로젝트 파일을 원본으로 보고 위키를 갱신한다.
코드, 씬, 프리팹, 패키지 또는 ProjectSettings 변경으로 기존 위키 내용이 달라지면 관련 노트만 함께 수정한다.
확인한 사실, 추론, 제안을 위키의 근거 규칙에 따라 구분하고 비밀 값이나 개인 설정은 기록하지 않는다.
